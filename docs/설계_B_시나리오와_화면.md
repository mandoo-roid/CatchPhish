# 설계 B: 시나리오와 화면 (10/24 최신)

담당: B / 상태: 서버에 반영된 내용(시나리오 9개 저장, 이메일 배점 확정)을 기준으로 정리함.

시나리오 카드의 원본은 `scenarios/scenarios.json`이고, 이 문서는 설명용이다. 두 곳이 다르면 `scenarios.json`이 맞다.

## 1. 시나리오 카드 양식

게임에 나오는 메일·문자 한 개를 아래 칸으로 적는다. 점수는 카드에 적지 않는다(점수는 탐지 엔진이 계산).

| 칸 이름 | 뜻 | 비고 |
|---|---|---|
| scenario_id | 카드 번호 (S01, S02 ...) | 중복 없이 |
| channel | 메시지 종류: email / sms / url | 결과지의 type(url / email)과 겹치지 않게 channel로 함. 칸 이름 사전 확정 |
| job_group | 어느 직군용인지: common 또는 직군 코드 | 직원의 직군(job)과 뜻이 달라 이름을 다르게 둠 |
| is_phishing | 피싱이면 true, 정상이면 false | 따옴표 없이 |
| case_type | 사례조사 유형 | A+C처럼 +로 잇고 공백 없이 쓴다. 정상은 null. 서버가 +로 나누기 때문에 A + C로 쓰면 결과 화면의 많이 속은 유형이 사라진다 |
| sender | 보낸 사람 | 이메일은 `이름 <주소>`, 문자는 `표시명 / 번호` 모양 |
| from | 이메일의 보낸 사람 헤더 | 이메일 카드만. 탐지 엔진에 넣을 메일 원문을 만들 때 쓴다 |
| reply_to | 이메일의 답장 주소 헤더 | 이메일 카드만. 없으면 null |
| auth_results | 메일 서버의 인증 검사 결과 | 이메일 카드만. 게임 속 설정값이다(실제 검사가 아님) |
| subject | 제목 | 문자는 null |
| body | 본문 | 실제 회사·사람 이름, 진짜 번호 쓰지 않기 |
| link | 본문 속 링크 | 없으면 null. 접속하지 않고 분석만 함 |
| attachment | 첨부 파일 이름 | 없으면 null |
| clues | 수상한 점 목록 | 각각 factor(이름)와 text(설명 문장) |
| explanation | 정답 해설 | 쉬운 말 2문장에서 3문장 |
| source | 참고한 사례 | 사례조사 번호 또는 가상 구성 (작품설명서용, 서버는 읽지 않음) |

### 카드를 쓸 때 지킬 규칙

- 링크는 `.example` 주소만, 전화번호는 `010-0000-0000`처럼 가짜 번호만 쓴다.
- auth_results는 `spf=pass smtp.mailfrom=도메인; dkim=pass; dmarc=pass` 모양으로 쓴다. **dkim=fail은 쓰지 않는다** (DKIM 점수가 0점이라 해설에 점수 없는 줄이 나옴).
- 정답·해설이 들어 있는 칸은 서버만 읽고, 화면에는 정답 관련 칸을 빼고 보낸다.

### 정답 규칙 (팀 결정 10/19)

- 행동 3개: click(링크·첨부 열기) / call(메시지에 적힌 번호로 전화) / official(공식 경로로 직접 확인)
- 피싱: click·call은 오답, official이 정답
- 정상: 모두 정답. 단 official은 과잉 의심으로 따로 집계
- 게임 속 가상 회사의 공식 주소는 company.example 로 가정한다

## 2. 시나리오 9개 (공통 4 + 직군별 1)

한 사람이 공통 4개와 자기 직군의 특화 1개, 모두 5문제를 푼다. 정상 메시지는 공통에 1개(S05)다. 직군별로 고르는 일은 서버(`api/index.py`의 pick_scenarios, A 담당)가 한다.

| 번호 | 직군 | 종류 | 피싱/정상 | 유형 | 소재 | 출처 | 엔진 점수 |
|---|---|---|---|---|---|---|---|
| S01 | common | 문자 | 피싱 | A+C | 건강보험 사칭 | 사례 1 바탕 | 확인 필요 |
| S05 | common | 메일 | 정상 | 없음 | 비밀번호 변경 공지 | 가상 구성 | 0 |
| S07 | common | 문자 | 피싱 | A+C | 수사기관 사칭 | 사례 6 바탕 | 25 |
| S08 | common | 문자 | 피싱 | A+C | 택배 사칭 | 사례 1 바탕 | 20 |
| S02 | hr | 메일 | 피싱 | A+C | 연말정산 첨부 | 사례 7 기법 바탕 | 83 |
| S03 | finance | 메일 | 피싱 | A+C | 대금 계좌 변경 | 가상 구성 | 10 |
| S04 | sales | 문자 | 피싱 | B+C | 텔레그램 사칭 | 사례 2, 3 바탕 | 확인 필요 |
| S09 | dev | 메일 | 피싱 | A+C | 개발 서비스 계정 경고 | 가상 구성 | 62 |
| S06 | office | 문자 | 피싱 | A+D | 정부24 지원금(연쇄형) | 사례 4, 5 바탕 | 확인 필요 |

엔진 점수는 10/24에 확인한 값이다. 이메일 카드는 이메일 엔진, 문자 카드는 링크 엔진이 계산한다.

### 카드마다 알려 주는 수상한 점

| 번호 | 수상한 점 (clues) |
|---|---|
| S01 | 발신자 불일치, 불안 압박 표현, 낯선 주소 |
| S05 | 수상한 점 없음, 비밀번호를 묻지 않음, 공식 경로 안내 (정상 메일) |
| S07 | 발신자 불일치, 공포 유발, 낯선 주소 |
| S08 | 발신자 불일치, 시간 압박, 낯선 주소 |
| S02 | 보낸 주소 불일치, 이중 확장자, 긴급성 압박 |
| S03 | 계좌 변경 요청, 전화 유도, 마감 압박, 낯선 발신 주소 |
| S04 | 도메인 유사, 보안 경고 사칭, 링크로 재로그인 요구 |
| S09 | 보낸 주소 불일치, 답장 주소 불일치, 시간 압박, 로그인 유도 |
| S06 | 기관 사칭과 지원금 미끼, 앱 설치 유도, 낯선 주소 |

### 카드를 만든 이유

- **S03:** 공격자가 진짜처럼 비슷한 도메인을 직접 등록하면 메일 인증을 통과한다. 점수가 낮아도 피싱일 수 있다는 점을 가르치는 카드라 점수가 일부러 낮다(10점).
- **S05:** 정상 메시지가 없으면 모두 의심하는 사람이 가장 좋은 결과를 받는다. 정상 메시지를 넣어 과잉 의심을 따로 센다.
- **S09:** 답장 주소 불일치 항목이 게임에 나오게 하려고 reply_to를 다른 도메인으로 둔 카드다.

## 3. 문진표 질문

게임을 시작하기 전에 직원이 답하는 질문 4개. 정답이 없고, 게임 결과와 비교하는 데 쓴다.

현재 화면에 쓰는 안내 문구: "정답이 있는 질문이 아닙니다. 평소 모습 그대로 답해 주세요. 답은 익명 번호로만 저장됩니다."

| 번호 | 질문 | 답 종류 | 선택지 | 쓰임 |
|---|---|---|---|---|
| Q1 | 수상한 메일이나 문자를 받으면 피싱인지 구분할 자신이 있다. | 1점에서 5점 | 1점(전혀 아니다)에서 5점(매우 그렇다)까지 | 자가평가 점수와 실제 정답률의 차이 |
| Q2 | 최근 1년 안에 피싱이 의심되는 메일·문자를 받아 본 적이 있나요? | 하나 고르기 | 없다 / 있었지만 그냥 지웠다 / 있었고 링크나 첨부를 열어 본 적이 있다 / 있었고 공식 경로로 확인했다 / 잘 모르겠다 | 경험에 따른 오답률 비교 |
| Q3 | 모르는 링크가 담긴 문자를 받으면 보통 어떻게 하나요? | 하나 고르기 | 링크를 눌러 확인한다 / 문자에 적힌 번호로 전화해 본다 / 공식 앱이나 대표번호로 직접 확인한다 / 무시한다 | 평소 습관과 게임에서 고른 행동의 차이 |
| Q4 | 최근 1년 안에 정보보안(피싱) 교육을 받은 적이 있나요? | 하나 고르기 | 있다 / 없다 / 기억나지 않는다 | 교육 경험에 따른 결과 비교 |

- Q3의 앞 3개 선택지는 팀이 정한 행동 3개(click / call / official)와 같다. 무시한다는 게임에 없는 행동이라 4번째로 추가했다.
- 직군 선택은 문진표가 아니라 시작 화면에서 한다(현재 구현).

| 화면 | 주소 | 보이는 것 | 서버 약속 |

| 첫 화면 | / | 피싱 대응 체험 시작 / 의심 링크 바로 검사 버튼 | 없음 |
| 시작 안내 | /game | 제목 캐치피싱, 안내문, 직군 버튼 5개, 시작하기 버튼(직군을 고르기 전에는 눌리지 않음) | 없음 |
| 문진표 | /game | 진행 표시(질문 n/4), 질문 하나씩, 이전·다음 버튼, 마지막은 게임 시작 | 1번 start |
| 문제 보기 | /game | 진행 표시, 메일 모양 또는 문자 모양 카드, 링크는 눌러도 열리지 않음(연습용이라 열리지 않아요 안내), 행동 버튼 3개 | 2번 answer |

### 해설의 결과 배너

| 상황 | 배너 문구 |

| 피싱에서 click 또는 call 선택 | 속았어요 |
| 정상에서 click 또는 call 선택 | 정상 메시지였어요. 괜찮아요 |

## 5. 이메일 배점 (B 확정 10/24)

항목별 최대 점수의 합이 100이다. 확인하지 못한 항목은 0점으로 처리하지 않고 unavailable에 적는다. 이메일 엔진은 헤더가 없으면 unavailable에 auth 하나만 적는다.

| 항목 (코드 이름) | 무엇을 보나 | 최대 점수 | 못 확인하면 unavailable | 비고 |
|---|---|---|---|---|
| DMARC 실패 | 발신 도메인 정책과 맞는지 | 28 | auth | |
| SPF 실패 | 보낸 서버가 허가된 서버인지 | 17 | auth | |
| DKIM 실패 | 메일 서명이 맞는지 | 0 | auth | 점수 없음. 게임 카드에도 나오지 않음 |
| 표시 이름 위장 | 부서 이름처럼 보이는데 주소는 회사 도메인이 아닌지 | 17 | 해당 없음 | |
| 답장 주소 불일치 | 답장 주소가 보낸 주소와 다른지 | 17 | 해당 없음 | |
| 첨부 파일 위험 | 이중 확장자 등 실행 파일 | 11 | 해당 없음 | |
| 긴급성·압박 문구 | 즉시, 벌금 등 | 10 | 해당 없음 | S03 점수가 일부러 낮은 의도를 지키려고 10점 유지 |
| 합계 | | 100 | | |

- 이전 임시값(25, 15, 10, 15, 15, 10, 10)에서 DKIM만 0으로 바꾸고, 긴급성은 유지하고, 나머지 5개 항목은 같은 비율(1.125배)로 늘려 합계 100에 맞췄다.
- 이메일 엔진은 SPF·DKIM·DMARC를 직접 검사하지 않고, 메일 헤더에 적힌 인증 결과를 읽어 점수로 바꾼다. 게임 카드의 auth_results는 시나리오 작성자가 정한 설정값이다.

## 7. 팀 논의 포인트

- 정상 시나리오 개수: 지금 1개(S05). 인수인계서에는 2개에서 3개로 적혀 있다.
- 링크 엔진에 본문 긴급성 키워드를 넣을지: 지금은 링크 주소만 분석해서 공포·압박 단서가 점수에 안 들어간다. 링크 배점 합계 100을 다시 나눠야 한다.
- 점수 판정 구간(임시: 60 이상 위험, 30 이상 주의)을 그대로 둘지.
- DKIM 0점의 설명: 신청서에 SPF·DKIM·DMARC 검증이 약속되어 있어서, 작품설명서에서 DKIM을 점수에 넣지 않은 이유를 어떻게 쓸지.
- 이메일 엔진 표현: 직접 검증이 아니라 헤더에 적힌 결과를 읽는다는 점을 작품설명서에 어떻게 쓸지.
- 문진표가 게임보다 먼저 나와서 피싱 체험이라는 걸 미리 알게 된다. 문진표를 게임 뒤로 옮길지.
- 문진표 안내문의 "익명 번호로만 저장됩니다"는 기록 저장(DB)이 연결되기 전에는 사실이 아니다.
- 서버가 카드 순서를 섞을지: 지금 공통 카드는 파일 순서대로 나와서 정상 메시지가 항상 같은 위치다.
