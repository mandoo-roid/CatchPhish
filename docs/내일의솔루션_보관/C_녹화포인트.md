# C 녹화 포인트 (증적 로그 포렌식)

> 작성: C (11/1). 드라이브에 이미 올린 C 영상 중, 제작 과정 영상(3분 이내)에 쓸 구간과 자막을 A(편집)에게 전달하는 문서예요.
> 약속: 한 사람 영상 합계 **1분 안**. 파일 이름은 드라이브에 올린 이름 그대로예요. 구간은 **영상 시작을 0초로 한 시간**이에요.
> 드라이브 원본은 그대로 두고 구간만 잘라 써요.

## 장면 1. 해시체인 핵심 코드

| 항목 | 내용 |
|---|---|
| 파일 이름 | `1019_C_hashchain테스트.mp4` |
| 쓸 구간 | **7초–14초** (실행 버튼을 누르고 결과가 나오는 부분) |
| 화면 | 5개 기록을 쌓아 `1) 정상: ok True, count 3`, `2) 2번 기록 수정: 기록 내용이 바뀜 (변조)`, `3) 2번 기록 삭제: 순번이 끊김`이 나옴 |
| 왜 필요한가 | C 파트의 출발점. "지문으로 기록을 이어 붙이고, 고치면 들킨다"는 핵심 아이디어를 제일 처음 보여 줌 |
| 자막 | ① "게임 결과를 기록마다 앞 기록의 지문과 묶었어요" ② "기록을 고치면 → 변조 발견" ③ "기록을 지우면 → 순번이 끊겨 발견" |

## 장면 2. 장부 저장과 변조 탐지

| 항목 | 내용 |
|---|---|
| 파일 이름 | `1025_C_ledger테스트.mp4` |
| 쓸 구간 | **4초–13초** (결과가 나온 뒤부터 끝까지) |
| 화면 | `test_ledger.py` 결과 4줄. 5건 저장 검증 통과, DB에서 2번 몰래 수정 → 변조 발견, 3번 삭제 → 순번 끊김, 5명이 동시에 8건씩 저장 → 40건 정상 |
| 왜 필요한가 | "기록을 고치면 바로 들킨다"가 **DB에 저장된 장부에서 실제로 작동**한다는 근거. 증적 로그의 핵심 장면 |
| 자막 | ① "결과를 DB 장부에 저장하고 검사해요" ② "DB에서 2번 기록을 몰래 고쳐도 → 발견" ③ "3번을 지워도 → 순번이 끊겨 발견" ④ "동시에 40건을 저장해도 오류 없음" |
