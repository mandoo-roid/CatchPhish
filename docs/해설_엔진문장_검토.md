# 해설의 "탐지 엔진 분석" 문장 검토

> B 작성 (11/15). 카드 28개(기존 14 + 개인용 8 + 직군 쌍둥이 5 + 연습용 S06 1)를 지금 엔진(링크 엔진 `url_analyzer.py`, 이메일 엔진 `email_analyzer.py`)에 넣어, 해설·단서에 적힌 말과 엔진 결과(점수·이유 문장)가 맞는지 대조했어요.
> 엔진 코드는 A 담당이라 B가 고치지 않았고, 고칠 점은 아래 "A에게"에 모았어요.

| 구분 | 결과 |

## 2. A에게 (엔진 쪽, 팀 논의)

### 2-1. "기관명 불일치" 이유 문장의 공식 주소 끝

- 지금 문장: "공공기관 이름을 내세웠지만 주소 끝이 정부 공식 주소(.go.kr)가 아닙니다."
- S01(건강보험 사칭)에도 이 문장이 나오는데, 공공기관 중에는 주소 끝이 .go.kr이 아닌 곳도 있어요(.or.kr 등). 체험자가 ".go.kr만 진짜"라고 배우면 다른 진짜 기관 주소를 의심할 수 있어요
- 제안: "주소 끝이 그 기관의 공식 주소가 아닙니다 (정부 기관은 보통 .go.kr)"처럼 넓히기. 각 기관의 실제 주소 끝은 확인 필요

### 2-2. 링크 엔진 공공기관 단어(ORG_WORDS)에 court 추가

- S01(health) 35점, 짝 S10(court) 20점. court가 목록에 없어서 "기관명 불일치 15점"을 못 받아요
- court를 넣으면 S10도 35점이 되어 쌍둥이 점수가 맞아요

### 2-3. 이메일 엔진이 학교 이름을 사내 부서처럼 알아보게 할지

- 개인용 P02(학교 포털)·P06(학교 클라우드)은 표시 이름이 학교인데 실제 주소는 바깥 주소예요. 지금 엔진은 회사 부서 이름(인사, 보안 등)만 알아봐서 "표시 이름 위장"을 못 잡고 0점이에요
- B가 정리할 "학교 공식 메일 도메인 목록"을 엔진에 넣으면 두 카드 모두 17점이 돼요 (짝끼리 같이 올라가서 쌍둥이는 그대로)
- 다만 양식(A 11/13)에 "P02는 엔진이 못 잡는 메일, 그래서 사람이 요구하는 행동을 봐야 한다"는 의도가 있어서, 넣을지는 팀 논의
