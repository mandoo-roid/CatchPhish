## 1. 체험자 입장

### 첫 화면

큰 버튼 세 개: **[개인용 체험] [기관용 체험] [자유 훈련]**
링크 검사와 대응 매뉴얼은 위쪽 메뉴(☰) 안에 있고, 컴퓨터에서는 사이드 바에 보여요. (C 제안, 11/11)

### [개인용 체험] (학생·일반인)

1. **사전질문:** 학생인지 일반인인지, 캐치피싱을 해 본 적 있는지, 피싱을 알아볼 자신이 있는지
2. **문자·메일 4개 도착:** 실제 문자 앱, 메일 앱처럼 생긴 화면으로 하나씩 와요
3. **행동 고르기:** 선택지 세 개가 모두 "확인한다"처럼 보여서, 메시지를 읽어야만 고를 수 있어요
4. **선택 미리보기 → 해설:** 고른 행동이 어떻게 되는지 잠깐 보여 주고, 무엇을 봤어야 했는지 알려 줘요
5. **연쇄형 체험:** 처음엔 평범했던 연락이 점점 수상한 부탁을 해요. 어디서 멈출지 골라요 (연습이라 점수에 안 들어가요)
6. **게임 훈련:** 메시지를 보고 "처리 / 멈춤"을 골라요
7. **문자·메일 4개 다시 도착:** 처음 보는 새 문제예요
8. **결과:** 사전과 사후 두 점수를 나란히 보여 줘요
   - **막은 피싱:** 피싱을 잘 멈췄나
   - **처리한 업무:** 정상 메시지까지 의심하지 않고 잘 처리했나
   - 보안 대응 수준, 맨 아래 **[더 알아보기: 링크 검사 / 대응 매뉴얼]**

### [기관용 체험] (회사·기관 직원)

1. **기관 코드 입력**
2. **직군 선택:** 인사, 재무, 영업, 개발, 일반 사무
3. **사전질문**
4. **문자·메일 4개:** 공통 문제 3개 + 내 직군에게만 오는 문제 1개
5. **해설 → 대응 매뉴얼 문장 따라 쓰기**
6. **연쇄형 체험** (연습)
7. **문자·메일 4개 다시 도착** (처음 보는 문제, 게임 없음)
8. **결과:** 두 점수 전후 비교, 맨 아래 [더 알아보기]

### [자유 훈련] (누구나)

1. 별명 정하기
2. 체험 없이 바로 게임
3. 점수가 순위표에 올라가요

## 2. 푸는 문제

사전(세트 A)과 사후(세트 B)는 **모양이 같은 쌍둥이 문제**예요. 그래야 실력이 늘었는지 공정하게 잴 수 있어요. 사람마다 A와 B 중 무엇을 먼저 볼지는 무작위예요.

### 기관용

| | 세트 A | 세트 B (쌍둥이) |
|---|---|---|
| 피싱 문자 (기관 사칭) | S01 건강보험 | S10 법원 등기 |
| 정상 메일 | S05 정보보안팀 | S13 인재개발팀 |
| 정상 문자 | S08 사내 우편실 | S14 사내 인사팀 |
| 직군 카드 (피싱) | 아래 표 | 아래 표 |

| 직군 | 세트 A (지금 있는 카드) | 세트 B (새로 쓸 쌍둥이) |
|---|---|---|
| 인사 | S02 인사팀 사칭 메일 | 인사 쪽 사칭 메일 |
| 재무 | S03 거래처 경리팀 사칭 메일 | 거래처 사칭 메일 |
| 영업 | S04 메신저 사칭 문자 | 메신저·고객 사칭 문자 |
| 개발 | S09 코드 저장소 계정 알림 메일 | 개발 도구 계정 알림 메일 |
| 일반 사무 | S07 수사기관 사칭 문자 | 기관 사칭 문자 |

- 새 직군 카드 5개는 기존 카드를 바탕으로 이야기만 바꾸는 쌍둥이
- S11(택배 문자), S12(전자결재 메일)는 게임 문제나 예비로 사용
- 예전 참여자는 이미 본 카드라, 처음 하는 사람 위주로 모집

### 개인용 (새로 8개, 쌍둥이 4쌍)

| | 세트 A (예시) | 세트 B (쌍둥이 예시) |
|---|---|---|
| 피싱 문자 (학교 사칭) | 장학금 계좌 확인 | 등록금 환불 신청 |
| 피싱 메일 (계정 사칭) | 학교 포털 비밀번호 만료 | 클라우드 저장공간 만료 |
| 정상 메일 | 학교 수강신청 안내 | 교수님 과제 공지 |
| 정상 문자 | 택배 도착 알림 | 알바 근무표 안내 |

- 세트마다 **문자 2 + 메일 2, 피싱 2 + 정상 2**
- 정상 메시지에도 "오늘까지" 같은 급한 말을 넣어서, 급하다고 다 피싱이 아니게
- 소재는 예시. 쌍둥이 규칙만 지키면 바꿔도 됨

## 3. 개발자 입장

### 첫 화면

- 큰 버튼 3개로 바꾸고, 링크 검사·대응 매뉴얼은 메뉴(☰)와 사이드 바로
- 개인용은 `game.html?mode=personal`, 기관용은 `game.html?mode=org`, 자유 훈련은 게임 화면으로. 주소 끝 꼬리표로 어느 길인지 알려 줌

### 문제 파일 (`scenarios/scenarios.json`)

카드마다 이름표 추가

- `audience`: 개인용 / 기관용
- `set`: A / B
- `pair`: 쌍둥이 번호 (A의 1번과 B의 1번이 같은 번호)
- 연쇄형 S06에는 연습용 표시

### 서버 (`api/`)

지금 있는 "1회차 → 다시 도전 2회차" 구조를 **사전 → 사후**로 그대로 씀. 새로 짜는 게 아니라 규칙을 바꾸는 것.

1. **시작:** 화면이 개인용·기관용, 대상을 보내면 서버가 세트 A나 B를 무작위로 골라 4문제를 줌. 기관용은 공통 3 + 그 직군 카드 1
2. **사후:** "만점이 아니면 다시 도전" → **모두 사후 체험**, 처음과 **반대 세트**
3. **연쇄형:** 사전과 사후 사이에 따로 주고, 장부에 연습 표시를 해서 비교 통계에서 뺌
4. **장부 새 칸:** 개인용/기관용, 세트, 대상, 해 본 적 있는지. 넣은 뒤 [기록 검사]가 그대로 "이상 없음"인지 확인

### 체험 화면 (`game.html`)

1. 기관용일 때만 직군 화면
2. 사전질문에 대상, 해 본 적 있는지 추가
3. **실제 같은 화면 틀 2개:** 문자 앱 1개, 메일 앱 1개. 카드 내용만 갈아 끼움. 메일은 보낸 사람 이름만 보이고, 누르면 주소가 보이게
4. **선택지 순서 섞기:** 보이는 순서만 섞고, 서버로 보내는 값(`click`/`call`/`official`)은 그대로
5. 개인용은 연쇄형 다음에 게임, 기관용은 따라 쓰기
6. **결과 화면:** 사전·사후 두 점수 나란히, 맨 아래 [더 알아보기]
7. **모바일:** 폰 기준으로 만들고, 컴퓨터에서는 가운데 폰 화면처럼

### 게임과 순위표

1. **게임 1개:** 메시지 한 줄을 보고 "처리 / 멈춤"을 고르는 방식 추천 (정상이 섞여서 과잉 의심도 연습). 종류는 팀 의견 받아 확정
2. **게임 점수는 체험 장부와 따로** 저장. 해시체인과 교육 통계를 건드리지 않게
3. **순위표:** 점수는 서버가 직접 계산, 별명은 길이·글자 검사, 같은 기록 반복 등록 막기

### 관리자 화면 (`frontend/admin.html`, `stats.py`)

1. 새 통계: 사전·사후 비교, 대상별, 해 본 적 있는지별 (계산 함수 C, 연결 A)
2. **관리자 로그인 추가.** 화면뿐 아니라 관리자 데이터 주소도 잠금

### 작품 보안 점검 (공격 → 막기 → 다시 공격)

| 점검 | 공격 | 막기 |
|---|---|---|
| 점수 조작 | 순위표에 조작한 점수 보내기 (A) | 서버가 점수 계산 (A) |
| 장부 위변조 | 테스트용 복사본에서 기록 고치기·지우기·끼워 넣기 (A) | [기록 검사]가 잡는지 확인, 한계 정리 (A) |
| 관리자 무단 접근 | 관리자 주소·데이터 주소 외부에서 접근 (C, 막기 전·후) | 관리자 로그인 (A) |
| 별명 칸 입력 | 별명 칸에 스크립트 넣기 (C, 막기 전·후) | 입력 검사, 글자 그대로 표시 (A) |

- 공격은 **우리 서비스에만**, 장부는 **테스트용 복사본에서만**
- 점검마다 4줄 기록: 무엇을 시도했나 / 왜 뚫렸나 / 어떻게 막았나 / 무엇을 배웠나
- 막기 전·후 화면 캡처

## 4. 이번에 하지 않는 것

- 화면 반 나누기 대결
- 선택지 버튼 대신 링크·번호를 직접 누르는 방식
- 마스코트 스티커
- 방 코드 대결은 순위표까지 끝나고 시간이 남을 때만. 못 하면 작품 설명서에 쓰지 않음
- 게임 시작 애니메이션은 교수님 의견 들을 때까지 보류

## 5. 이렇게 하는 이유

- **교육성과 중심:** 모든 길이 "처음 → 배우기 → 다시"로 끝나서, 교육성과(25점)의 근거인 전후 비교가 흐름의 중심
- **공정한 비교:** 쌍둥이 세트 + 무작위 순서 + 전원 사후 체험. "문제가 쉬워져서 오른 것 아닌가?"에 답할 수 있고, 1·2차 시범 운영 한계를 고친 근거
- **실제처럼:** 실제 문자·메일 같은 화면 + 정답이 보이지 않는 선택지라, 시험이 아니라 실제 판단을 하게 됨 (교수님 제안)
- **작업량 줄이기:** 이미 있는 "1회차 → 2회차" 구조를 그대로 써서 서버를 새로 짜지 않음
- **기술성:** 보안 점검으로 교육 기록과 순위표를 믿을 수 있게 함
- **대상 확장:** 개인용과 자유 훈련으로 학생·일반인까지 넓힘 (지역사회 심사 근거)
- **첫 화면 정리:** 체험·게임에 집중하고, 부가 기능은 체험이 끝난 자리에서 이어짐 (C 제안)
