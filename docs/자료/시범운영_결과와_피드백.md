# 시범 운영 결과와 피드백 (10/31)

> 캐치피싱 시범 운영 기록. 작품설명서 성과·발전 방향과 교내 전시회 수정에 쓴다.
> 작성: A (10/31). 숫자는 관리자 화면과 DB(읽기 전용 조회)로 확인한 값. 피드백은 받은 말을 바꾸지 않고 내용별로 묶었고, 이름은 적지 않음

## 1. 운영 방법

- 기간: 10/31 새벽 장부를 비우고 해시체인 보완판으로 새로 시작 ~ **10/31 오후 9시 마감**
- 방법: 팀원이 지인에게 첫 화면 링크를 보내 부탁 (A 9명, B 14명, C 2명, 모두 25명). 안내: 새로고침하지 말고 결과 화면까지 한 번에, 한 사람당 한 판, 실제 업무와 가까운 직군, 개인정보는 저장되지 않고 익명으로만 기록, 끝나고 의견
- 시범 운영 중에는 팀원도 플레이하지 않음

## 2. 결과 (10/31 오후 9시 기준)

| 항목 | 값 |
|---|---|
| 끝까지 완료한 체험 | **38건** |
| 중간 이탈 | 5건 (답 6개, 전체 답 196개 중 3%) |
| 관리자 화면 참여 인원 | 43 (완료 38 + 이탈 5) |

| "자신 있다"(4·5점) / "자신 없다"(1~3점) 오답률 | 6% / 13% |
| 직군별 오답률 (3명 이상) | 개발·IT 0%, 인사 12%, 일반 사무 7%, 영업·고객 9% |

| 직군별 체험 수 | 일반 사무 26, 영업·고객 7, 인사 5, 개발·IT 3, 재무·회계 2 (3명 미만이라 관리자 표에서 제외) |

**쓸 때 주의**
- "명"이 아니라 **"건"**: 기록은 익명 번호로만 남아 같은 사람의 재참여나 링크 전달은 구별할 수 없다 (부탁 25명, 완료 38건)
- 비율은 중간 이탈 답 6개를 포함한 196개 기준
- 직군별 체험 수가 고르지 않아 직군 간 비교는 참고 수준

## 3. 피드백

> 출처 표시: **[B 전달]** B가 부탁한 사람들의 의견을 모아 전한 것 / **[C 전달]** C가 전한 의견 / **[A]** A가 직접 받은 의견. 오른쪽 칸은 내일의 솔루션에서는 발전 방향으로 쓰고, 교내 전시회 때 수정한다 (A 결정)

| 묶음 | 받은 피드백 (요지) | 발전 방향 / 전시회 수정 |
|---|---|---|
| 결과 화면 글이 많음 | [B 전달] 결과 화면에 글이 너무 많고 게임이 끝났을 때 임팩트가 없다는 의견이 많았음, 간략히 요점 정리하고 상세 설명은 보고 싶을 때 보게 / [B 전달] 속았을 때 왜 속았는지 간결하게, 글이 많아 잘 안 읽힘 / [A] 해설이 더 눈에 띄면 좋겠음, 가시성 | 결과·해설을 요점 한 줄 + 펼쳐 보기로 |
