## 0. AI에게: 이 대화에서 지켜야 할 규칙

너는 지금부터 보안 캡스톤 프로젝트 "캐치피싱"을 돕는다. 아래 내용을 모두 기억한 채로 대화해 줘.

1. **나는 완전 초보야.** GitHub, Colab, 파이썬 모두 처음이야. 초등학생에게 설명하듯 버튼 위치까지 하나씩 알려 주고, "무엇을"과 함께 **"왜"**를 꼭 설명해 줘.
2. **코드는 셀(조각) 하나씩** 줘. 코드 줄 아래에 `# 하는 일:` / `# 이유:` / `# 참고:` 형식으로 각주를 달아 줘. 셀마다 **"나와야 할 결과 | 맞는지"** 표를 붙여 줘. 내가 결과를 캡처해서 보내면 그 표와 대조해 확인해 줘.
3. **녹화 포인트는 그 단계를 하는 바로 그때** 알려 줘 (마지막에 몰아서 X). 형식: `🎬 녹화 | 파일명(예: 1019_시나리오설계.mp4) | 장면 | 길이(10초에서 40초) | 쓰임(초기/중기/완성)`. API 키·이메일 주소·비밀번호·개인정보가 화면에 나오면 주의를 줘.
4. **매 답변 끝에 AI 활용내역**을 `도구 / 목적 / 활용 범위` 형식으로 정리해 줘. 대화가 끝날 때는 아래 9번의 기록표 칸 형식으로 정리해 줘. 내가 직접 한 일과 AI가 한 일을 구분해서 적어 줘.
5. 팀이 같이 정해야 할 것(배점, 기준, 직군 목록 등)은 **네가 정하지 말고** "팀 논의 포인트"로 표시해 줘. 초안을 제안하는 건 괜찮아.
6. 피싱 링크는 **분석만 하고 접속하지 않는다.** 연습용 주소는 `.example`을 쓴다. 실제 수집한 피싱 데이터·개인정보·API 키는 저장소에 올리지 않는다.
7. "누가 언제까지 해 줘야 진행된다"는 계획은 짜지 마.
8. 아래 "칸 이름 사전"의 이름을 그대로 써 줘. 바꾸고 싶으면 바꾸자고 **제안만** 하고, 바꾼 이름은 따로 표시해 줘.
9. 저장소 `main`에 저장하면 **웹사이트가 바로 바뀐다**(Vercel 자동 배포). 서버 코드(`api/`, `backend/`)를 고치는 안내를 할 때는, 올리기 전에 꼭 확인할 점을 알려 주고 "A에게 단톡으로 먼저 알리기"를 안내해 줘.

## 1. 프로젝트 한눈에 보기

- **작품명:** AI 기반 피싱 탐지 및 기업 보안 교육 체험 플랫폼 "캐치피싱(CatchPhish)"
- **팀:** Phish&Chips (배화여자대학교 소프트웨어공학과 3학년 3명), 지도교수 김현우, 산업체 ㈜푸르고
- **한 줄 요약:** 회사 직원이 가짜 메일·문자·링크가 나오는 **시나리오 게임**을 하고, 속았을 때 **탐지 엔진이 "왜 위험했는지" 설명**하며, 기록은 **해시체인으로 위변조를 검사할 수 있게 저장**하고, 회사는 **직군별로 어떤 피싱에 약한지** 통계로 보는 웹 프로그램
- **신청서에 약속한 수행 방법 (신청서는 수정 불가):** ① 파이썬 머신러닝 기반 URL·이메일 피싱 판정 + 요소별 위험도 점수 분해 ② 이메일 헤더(SPF/DKIM/DMARC) 검증 + SHA-256 해시체인 기반 무결성 증적 로그 ③ 탐지 엔진과 연동한 시나리오 게임 → 기업용 보안 교육 플랫폼 ④ 체험 결과 DB 축적 → 직군·시나리오별 오답률, 취약 패턴 집계 ⑤ 집계 결과 기반 개인별 맞춤 피드백
- **결과물:** 캐치피싱 프로그램, 캐치피싱 활용 가이드 / 활용 기술(안): Python, scikit-learn, dnspython, hashlib, Flask/FastAPI, PostgreSQL
- **목표:** 지금은 「내일의 솔루션」(기업 임직원 대상). 12월 교내 전시회용 쉬운 버전은 나중에 엔진을 재사용해 만든다

## 4. 지금 상태 (10/31)

### 웹사이트

- **배포 주소:** https://catchphish-three.vercel.app
  - `/` 첫 화면: "피싱 대응 체험 시작" / "의심 링크 바로 검사"
  - `/game` 게임: 시작 안내(직군 선택) → 문진표 4개 → **문제 5개 (공통 4 + 내 직군 1, 순서는 매번 섞임, 정상 2개)** → 해설 → 내 결과. 문제·해설 화면 왼쪽에 PC 사내 메일 또는 휴대폰 문자 화면. 문자 해설에는 본문의 압박 문구를 따로 보여 줌. 연쇄형 카드(S06)는 2·3단계 화면을 거침. 링크가 있는 카드 해설에는 "AI 판단" 한 줄. 문제마다 제한 시간(문자 15초, 메일 25초)이 보이고, 시간이 지나도 답은 고를 수 있음. 결과 화면에 "제한 시간 안에 고른 문제 ○/5" (10/30). 선택지는 "링크·첨부를 열어 바로 처리한다 / 적힌 번호로 전화해 처리한다 / 처리를 멈추고 따로 확인한다"이고, 메시지에 링크·첨부나 전화번호가 없으면 그 버튼은 흐리게 나옴 (10/31). 결과 화면 맨 위에 판정 한 줄과 **두 점수(막은 피싱 ○/○, 처리한 업무 ○/○)**, 속은 횟수 (10/31). "이렇게 해 보세요"는 C의 `feedback.py`가 고른 맞춤 팁(유형 팁, 전화 팁, 다 맞히면 칭찬. 하나도 안 속았지만 업무가 멈춘 판에는 노란 상자가 대신 설명), "같은 직군 평균 오답률 ○% · 내 오답률 ○%" 한 줄 (같은 직군 3명 이상일 때만, 10/30)
  - `/check` 링크 직접 검사. 위험 점수 아래에 "AI 판단" 한 줄 (60% 이상만 확률)
  - `/admin` 관리자 화면: 회사 코드로 입장. 통계(참여 인원, 과잉 의심, 자신감 있다/없다 오답률, 직군별 오답률, 많이 속은 유형)와 [기록 검사] 작동(10/29). 참여 인원 3명 미만 직군은 표에서 뺌. 정식 회사 코드로 바꾸고 실제 화면 확인(10/30, 코드는 말로만 공유)
  - ⚠️ **시범 운영 중 (10/31부터):** 장부를 비우고 해시체인 보완판으로 새로 시작했어요. 지금부터 장부에 쌓이는 기록은 작품설명서 성과(시범 운영 숫자)로 써요. **팀원도 게임을 플레이하지 않아요** (실수로 했으면 몇 판인지 A에게). 링크 검사(`/check`)는 장부에 기록되지 않아요
- **배포 방식:** `main`에 저장하면 Vercel이 1분에서 3분 안에 자동 배포. Vercel 관리 화면은 A 계정에서만 보인다
- **게임 기록:** 답할 때마다 장부(DB)에 한 줄씩 저장된다 (10/28부터, 서버 약속 7번). 10/31부터 C의 해시체인 보완판(`ledger_v2.py`, `hashchain_v2.py`): 비밀 열쇠(HMAC, Vercel 환경 변수 `HASH_SECRET`)와 끝 기록 삭제 감지(`ledger_head` 표)
- **연쇄형(S06):** 서버, 단계 문장, 게임 화면 모두 연결됨(10/29). S06에서 링크를 열면 2단계 → 3단계 화면이 나오고, 단계마다 "계속"과 "멈춤"을 고름. 끝나면 해설과 멈춘 단계가 나옴. 2·3단계에서 멈추면 노란 "중간에 멈췄어요" 배너 (B 10/29, 채점은 그대로)
- **AI 모델:** 연결됨(10/29). 링크 엔진 결과지의 `model_probability`에 피싱 확률이 들어감. 위험 점수에는 더하지 않음

| 칸 | 뜻 |
|---|---|
| `type` | `url` 또는 `email` |
| `input` | 검사한 링크 주소 또는 메일 파일 이름 |

| `unavailable` | 확인 못 한 항목 (`whois` = 도메인 생성일 조회 실패, `spf` = 메일 검사 결과 없음, `auth` = 이메일 헤더에 인증 결과 없음). 0점 처리하지 않는다 |

| `email_spoof.json` | 62 | DMARC 실패 28 / SPF 실패 17 / 답장 주소 불일치 17 | 이메일 실험 노트북의 연습 메일을 현재 엔진으로 다시 생성 (10/28) |

### 탐지 엔진 배점

- **링크(초안):** 도메인 유사 35 / 생성일 30 / 기관명 불일치 15 / 키워드 10 / URL 구조 10 = 100. 정부 사칭 연습 링크는 처음 0점이었다가 보완 후 60점, 텔레그램 사칭 20점 → 55점, 진짜 사이트(구글, 정부24, 네이버 로그인, 카카오)는 0점
- **이메일(B 확정 10/24):** DMARC 28 / SPF 17 / DKIM 0 / 표시 이름 위장 17 / 답장 주소 불일치 17 / 첨부 파일 위험 11 / 긴급성·압박 문구 10 = 100
  - 엔진은 SPF·DKIM·DMARC를 직접 검사하지 않고, 메일 헤더에 적힌 인증 결과(`auth_results`)를 읽어 점수로 바꾼다
  - 카드에 `dkim=fail`은 쓰지 않는다 (0점이라 해설에 점수 없는 줄이 나옴)
  - DKIM을 0점으로 둔 이유 (B): 메일링 리스트나 보안 장비가 제목·본문을 고치면 정상 메일에서도 DKIM 서명이 자주 깨져, 점수를 주면 정상 메일을 위험하다고 잘못 판정하기 때문 (자세한 문장은 설계 B 5번)
- **게임 시나리오 엔진 점수:** S01 35 / S02 83 / S03 10 / S04 55 / S05 0 / S06 60 / S07 25 / S08 0 (10/29 정상으로 새로 씀) / S09 62
  - S03(거래처 메일)은 점수가 낮다. 공격자가 비슷한 주소를 직접 등록하면 메일 인증을 통과하는 실제 수법이라, 해설에 "탐지 점수가 낮아도 피싱일 수 있어요"를 넣었다

### AI 모델 (URL 피싱 확률)

- **학습 데이터:** PhiUSIIL Phishing URL (Website), UCI Machine Learning Repository 967, Arvind Prasad·Shalini Chandra (2024), DOI https://doi.org/10.1016/j.cose.2023.103545, 라이선스 CC BY 4.0. 데이터는 Colab 안에서만 쓰고 저장소에 올리지 않는다
- **모델:** 로지스틱 회귀(scikit-learn, Colab에서 학습). 서버에는 학습 결과 숫자만(`url_model.json`) 가져가 같은 계산을 한다 (Vercel 크기 제한)
- **특징 9개 (주소 글자만, 접속 안 함):** 등록한 이름(예: `accounts.google.com`이면 `google`)의 길이·하이픈·숫자 / 앞에 붙은 이름(www 제외)의 하이픈·숫자 / IP 주소 / @ 기호 / 등록한 이름의 유도 단어(login, verify 등) / 무료 호스팅. `.example` 연습 주소는 `.com`처럼 계산
- **성능 (시험용 47,159개):** 정확도 76.5%, 정밀도 94%, 재현율 48%, AUC 0.779
- **쓰는 방법:** 결과지 `model_probability`에 확률을 넣고, 화면에는 60% 이상일 때만 숫자를 보여 준다 (10/29 결정, 10/29 연결). 위험 점수(규칙 기반)는 바꾸지 않는다
- **서버 계산:** `url_analyzer.py`의 `model_features`는 노트북 셀 6의 `features`와 같은 계산이다. 유도 단어·무료 호스팅 목록이나 특징을 바꾸면 노트북에서 다시 학습하고 `url_model.json`도 바꿔야 한다
- **한계 (작품설명서에 그대로):** 학습 데이터의 정상 주소가 첫 화면(`www.이름.com`) 위주라, 주소 글자만으로는 깔끔한 사칭 주소를 구별하지 못한다. 한국 기관·택배 사칭 주소로 다시 학습하는 것은 발전 방향

### 연쇄형 카드 데이터 (S06 `chain` 칸)

- `chain`은 2단계부터의 화면 목록이다. 칸마다 `title`(화면 제목) / `body`(본문) / `continue_label`(계속 버튼) / `stop_label`(멈춤 버튼) / `stop_explanation`(멈췄을 때 해설), 마지막 단계에만 `end_explanation`(끝까지 갔을 때 해설)
- 문장은 B가 설계 B 2-1에서 정한다. 화면에 보여 줄 칸만 단계마다 보내고, 해설은 체험이 끝날 때 서버가 보낸다

### 장부 저장 약속 (C, 바꾸면 기록 검사가 틀어짐)

- ⚠️ **10/28부터 실제 사이트에서 사용 중 (10/31부터 보완판 `ledger_v2.py`·`hashchain_v2.py`).** 고치면 바로 게임 기록 저장이 바뀐다. Colab에서 먼저 시험하고, 올리기 전에 A에게 알린다. HMAC처럼 지문 계산을 바꾸는 수정은 A가 장부를 비우는 시점과 맞춘다
- 테이블 하나 `ledger(seq, prev_hash, record, created_at, hash)`. `record`는 **JSONB가 아니라 TEXT**, `created_at`도 **글자** 그대로 저장한다 (지문 계산에 쓴 글자와 같아야 함)
- 지문 = `SHA-256( canonical({seq, prev_hash, record, created_at}) )`, 첫 기록의 `prev_hash`는 `"0"` 64개. **보완판은 환경 변수 `HASH_SECRET`이 있으면 HMAC-SHA256** (10/31부터 Vercel에 등록됨, 값은 공유하지 않음)
- **보완판 `ledger_head` 표:** 마지막 번호·마지막 지문·도장(head_mac)을 기록과 같은 트랜잭션에서 갱신. [기록 검사]는 head를 먼저 읽고 장부와 맞춰 봐서 **끝 기록 삭제**도 잡는다
- **장부를 비울 때는 `ledger`와 `ledger_head`를 둘 다** 비운다. 열쇠를 바꾸면 그 전 기록은 전부 "변조"로 나온다
- 같은 `seq`가 동시에 들어오면 마지막 기록을 다시 읽고 최대 8번 재시도
- `DATABASE_URL`이 있으면 Neon Postgres, 없으면 SQLite (Colab 시험용). **C는 진짜 DB에 접속하지 않고 Colab SQLite로 시험한다**
  - Colab 시험법: 새 노트북 왼쪽 파일 패널에 `ledger.py`, `test_ledger.py`(그리고 새로 만든 파일)를 올리고, 아래로 `hashchain.py`를 받은 뒤 실행. 파일들이 같은 폴더에 있어야 한다
    `!wget -q https://raw.githubusercontent.com/mandoo-roid/CatchPhish/main/backend/db_logs/hashchain.py` → `!python test_ledger.py`
- 해시체인은 변조를 **막는 것이 아니라 들키게 하는 것**이다. 작품설명서에는 "위변조 탐지·검증"이라고 쓴다
- **알려진 한계 (C, 작품설명서에 이대로):** 열쇠가 노출되면 보호가 약해진다. DB와 Vercel 설정을 **둘 다** 가진 사람은 막지 못한다 / 열쇠가 없는 상태(Colab 시험)에서는 "끝 기록을 지우고 head도 되돌리는" 공격을 못 잡는다 (열쇠를 켜면 잡힘) / 저장에 실패한 기록은 장부에서 빠져서 [기록 검사]가 찾지 못한다
- **장부 한 줄 10칸** (`docs/설계_A_흐름과_서버약속.md`): `anon_id`, `job`, `self_check`, `scenario_id`, `case_type`, `is_phishing`, `choice`, `is_correct`, `over_suspicion`, `analysis`

### 게임 흐름과 채점

1. 직군 선택 → 2. 문진표 4개(Q1 자신감 1점에서 5점) → 3. 시나리오마다 **행동 3개 중 하나** → 4. 해설("속았어요 / 잘 막았어요 / 정상 메시지였어요 / 과잉 의심") + 수상한 점 + 탐지 엔진 분석 → 5. 결과(판정 한 줄, 두 점수: 막은 피싱·처리한 업무, 속은 횟수, 자신감 vs 실제, 약한 유형, 맞춤 팁, 같은 직군 평균 비교, 제한 시간, 업무 지연)

| 시나리오 | `click` 링크·첨부를 열어 바로 처리 | `call` 적힌 번호로 전화해 처리 | `official` 처리를 멈추고 따로 확인 |
|---|---|---|---|
| 피싱 | 오답 | 오답 (보이스피싱 함정) | 정답 |
| 정상 | 정답 | 정답 | 정답, 단 과잉 의심으로 따로 집계 (결과의 "처리한 업무"에서 빠짐) |

보안 원칙: 정답·해설은 화면에 **미리 보내지 않고**, 채점은 **서버가** 한다. 입력은 정해진 값만 받는다. 링크에는 **접속하지 않는다.**

## 10. 지금까지 실제로 한 실수 (같은 실수 방지)

- 새 파일을 만들려다 **기존 파일 이름을 바꿈** (Rename) → 새 파일은 Add file → Create new file로
- 삭제·업로드 후 마지막 초록 **Commit changes** 버튼을 안 누름 → 반영 안 됨
- 다시 올릴 때 파일 이름이 `url_practice (1).ipynb`, `game_B (1).html`처럼 바뀜 → 덮어쓰기가 아니라 파일이 2개가 됨. 올리기 전에 내 컴퓨터의 파일 이름 확인, 내용만 바꿀 때는 연필로 고치기
- 다른 폴더에 엉뚱한 파일을 올림 → 올리기 전에 **폴더 위치와 파일 이름** 확인
- Colab을 다시 열면 **셀 1부터 다시 실행**해야 함
- 커밋 메시지를 안 적으면 `Add files via upload`가 자동으로 붙음
- 폴더는 저절로 안 생긴다. 새 파일 이름 칸에 `api/index.py`처럼 **`/`를 넣어야** 폴더가 생긴다
- Colab의 "`.py`로 다운로드"는 시험 코드까지 같이 들어간다 → 서버용 `.py`에는 함수만 남기기
- `main`에 올리면 웹사이트가 바로 바뀐다. 서버 코드는 올리기 전에 한 번 더 확인
- 표의 한 줄을 마우스로 세 번 클릭해서 붙여넣으면 줄이 합쳐진다 → 줄 안을 클릭하고 `Home`, `Shift+End`로 선택
- 마크다운 한 줄에 물결표가 두 번 나오면 그 사이 글자가 취소선이 된다 → "에서", "부터"를 쓰기
- 마크다운에서 꺾쇠로 감싼 주소는 글자가 사라진다 → 백틱(`)으로 감싸기
- `case_type`을 `A + C`처럼 띄어 쓰면 서버가 유형을 못 읽는다 → `A+C`로 붙여 쓰기
- 연필로 파일 전체를 바꿀 때 **붙여넣기가 두 번** 되어 문서가 두 벌이 됨 → 붙여넣은 뒤 맨 아래 "마지막 수정" 줄이 **한 번만** 있는지 확인
- 배포 직후 **이미 열려 있던 화면**으로 시험하면 옛 화면이 쓰여 새 기능이 안 됨 (10/28 장부 저장) → `Ctrl+Shift+R`로 새로고침 후 시험
