## 1. 프로젝트 한눈에 보기

- **작품명:** AI 기반 피싱 탐지 및 기업 보안 교육 체험 플랫폼 "캐치피싱(CatchPhish)"
- **팀:** Phish&Chips (소프트웨어공학과 3학년 3명), 지도교수 김현우, 산업체 ㈜푸르고
- **공모전:** 2026 「내일의 솔루션」 캡스톤디자인 공모전 (교내 선발 → 상위 2팀 협의회 제출)
- **한 줄 요약:** 이메일·문자·링크 피싱을 AI가 분석하는 과정을 **시나리오 게임**으로 체험하게 해서, 기업 직원의 피싱 대응력을 키우는 웹 프로그램

### 신청서에 약속한 수행 방법

1. 파이썬 머신러닝 기반 URL·이메일 피싱 판정 + 요소별 위험도 점수 분해
2. 이메일 헤더(SPF/DKIM/DMARC) 검증 + SHA-256 해시체인 기반 무결성 증적 로그
3. 탐지 엔진과 연동한 시나리오 게임 → 기업용 보안 교육 플랫폼
4. 체험 결과 DB 축적 → 직군·시나리오별 오답률, 취약 패턴 집계
5. 집계 결과 기반 개인별 맞춤 피드백

### 샘플은 왜 만들었나? (가장 중요)

세 명이 따로 만들어도 나중에 **딱 맞게 연결되도록 정한 "결과 모양 약속"**이다. 이어달리기에서 바통 모양을 맞추는 것과 같다.

```
A(링크 분석) ─┐
              ├─ 결과(JSON) ──→ B가 화면(게임 해설)에 보여줌
B(이메일 분석)─┘             └→ C가 장부(해시체인 로그)에 저장
```

모든 분석 결과는 이 6칸으로 만든다:

| 칸 | 뜻 |
|---|---|
| `type` | `url` 또는 `email` |
| `input` | 검사한 링크 주소 또는 메일 파일 이름 |
| `score` | 위험 점수 0~100. **반드시 `reasons`의 `points` 합계** |
| `model_probability` | AI 모델의 피싱 확률 0~1. 모델이 없으면 `null` |
| `reasons` | 이유 목록. 각각 `factor`(이름) / `points`(점수) / `text`(설명 문장) |
| `unavailable` | 확인 못 한 항목 이름 목록 (`whois` = 도메인 생성일 조회 실패, `spf` = 메일 검사 결과 없음). 0점 처리하지 않고 여기 적는다 |

B는 샘플만 보고 화면을, C는 샘플만 보고 저장 기능을 **A의 엔진이 완성되기 전에도** 만들 수 있다. 이게 샘플의 목적이다.

### 샘플 3개가 각각 보여주는 것

| 파일 | 점수 | 이유 | 보여주는 상황 | 만든 방법 |
|---|---|---|---|---|
| `url_dangerous.json` | 75 | 도메인 유사 35 / 생성일 30 / 키워드 10 | 유명 이름(naver)을 따라 한 위험 링크. 모델 확률이 있는 경우 | 손으로 작성. 0.91은 **가짜 예시 값** |
| `url_whois_fail.json` | 60 | 도메인 유사 35 / 기관명 불일치 15 / URL 구조 10 | 정부기관(gov) 사칭. 생성일 조회 실패 → `unavailable: ["whois"]` | 노트북 셀 7~10이 생성 |
| `email_spoof.json` | 70 | SPF 실패 40 / 보낸 사람 불일치 30 | 인사팀 사칭 위조 메일. 모델 없음 → `null` | `email_practice.ipynb`가 생성 |

세 샘플을 합치면 링크 배점 5개 항목이 모두 한 번씩 나온다.

### 링크 배점 (초안)

도메인 유사 35 / 생성일 30 / 기관명 불일치 15 / 키워드 10 / URL 구조 10 = 100. 이메일 배점은 B가 정한다 (현재 40/30은 임시값).

### 노트북 `url_practice.ipynb` 구성

| 셀 | 내용 |
|---|---|
| 1 | 도구 설치 (`tldextract`, `Levenshtein`, `python-whois`) |
| 2~4 | 주소 나누기 / 글자 차이 세기 / 도메인 생성일 조회 연습 |
| 5 | `analyze_url_sample(url)`: 도메인 유사·키워드·생성일 검사 (샘플 1 함수) |
| 6 | 진짜/가짜 주소 비교 시험 |
| 7 | 샘플 2 주소를 셀 5에 넣으면 **0점** → 문제 발견 (주소 앞부분에 숨긴 이름을 못 찾음) |
| 8 | `analyze_url_v2(url)`: 셀 5 + 앞부분 이름 검사 + 기관명 불일치 + URL 구조 |

`email_practice.ipynb`(샘플 3)는 A가 만들었고, **B가 받아서 `backend/email_analyzer/`에 올릴 예정**이다. 이 폴더는 아직 없으므로 **Add file → Create new file** → 이름 칸에 `backend/email_analyzer/README.md` 입력(슬래시 `/`를 치면 폴더가 생김) → 내용 한 줄 쓰고 커밋 → 그 폴더에서 **Upload files**로 노트북을 올린다.

- 개발 환경: **GitHub Codespaces** (브라우저에서 코딩, 설치 불필요)
- 서버: Flask / DB: SQLite (신청서의 PostgreSQL은 "안"이었으므로 변경 가능. 작품설명서에 "확대 시 전환 가능"으로 기재)
