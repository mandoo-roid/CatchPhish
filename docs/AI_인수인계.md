## 0. AI에게: 이 대화에서 지켜야 할 규칙

너는 지금부터 보안 캡스톤 프로젝트 "캐치피싱"을 돕는다. 아래 내용을 모두 기억한 채로 대화해 줘.

1. **나는 초보야.** 버튼 위치까지 하나씩 알려 주고, "무엇을"과 함께 **"왜"**를 꼭 설명해 줘.
2. **코드는 조각 하나씩** 줘. 코드 줄 아래에 `# 하는 일:` / `# 이유:` / `# 참고:` 각주를 달고, **"나와야 할 결과 | 맞는지"** 표를 붙여 줘.
3. 팀이 같이 정해야 할 것(배점, 기준, 화면 구조 등)은 **네가 정하지 말고** "팀 논의 포인트"로 표시해 줘. 초안 제안은 괜찮아.
4. **사실이 아닌 내용은 넣지 않는다.** 숫자는 이 파일에 있는 값만 쓴다. 모르면 "확인 필요"라고 한다.
5. 피싱 링크는 **분석만 하고 접속하지 않는다.** 연습용 주소는 `.example`, 전화번호는 가짜 번호만. 실제 피싱 데이터·개인정보·API 키는 저장소에 올리지 않는다.
6. "누가 언제까지 해 줘야 진행된다"는 계획은 짜지 마.
7. 아래 "칸 이름 사전"의 이름을 그대로 써 줘. 바꾸고 싶으면 **제안만** 해 줘.
8. `main`에 저장하면 **웹사이트가 바로 바뀐다**(Vercel 자동 배포). 서버 코드를 고치는 안내를 할 때는 올리기 전에 확인할 점과 "A에게 단톡으로 먼저 알리기"를 안내해 줘.
9. 파일을 고쳐 줄 때는 **커밋 문구도 함께** 알려 줘. 형식: `[담당] 무엇을 했는지`. 여러 파일이면 파일별로, 올리는 순서도 함께.

## 1. 프로젝트 한눈에 보기

- **작품명 (교내 경진대회, 11/09 변경):** AI 기반 피싱 탐지 및 체험형 보안 교육 플랫폼 "캐치피싱(CatchPhish)"

  - 바꾼 이유: 대상을 회사원에서 학생·일반인까지 넓혀서 "기업"을 뺐다. 기관용·개인용을 모두 담고, 같은 작품을 이어서 발전시킨 것이 보이도록 나머지는 그대로 뒀다. 참가신청서와 작품 설명서에 같은 이름을 쓴다

- **산업체 ㈜푸르고:** 아직 미팅·협업 없음. 미팅 일정이 곧 잡힐 예정. **미팅 전에는 작품설명서·발표에 협업·요구 반영 표현을 쓰지 않는다.** 미팅 뒤에는 들은 말을 날짜와 함께 그대로 메모한다

- **지금까지:** 「내일의 솔루션」 캡스톤디자인 공모전 최종 제출 끝 (11/4, 작품설명서 PDF + 제작 영상). 교내 선발은 수상하지 못함 (11/10 안내 메일)

자세한 건 `docs/교내경진대회_흐름_설명.md`(체험자·개발자 입장 설명)와 `docs/교내경진대회_흐름과_포스터.md`(전체 정리·포스터)

**1. 흐름**

```
첫 화면: [개인용 체험] [기관용 체험] [자유 훈련]
         링크 검사·대응 매뉴얼은 메뉴(☰)와 사이드 바, 결과 화면 맨 아래 [더 알아보기]

개인용(학생·일반): 사전질문 → 사전 체험 4개 → 해설 → 연쇄형(연습) → 게임 → 사후 체험 4개 → 전후 비교
기관용(직원):     기관 코드 → 직군 → 사전질문 → 사전 체험 4개 → 해설 → 따라 쓰기 → 연쇄형(연습) → 사후 체험 4개 → 전후 비교
기관용(담당자):   관리자 화면 (새 통계 + 관리자 비밀번호)
자유 훈련:        별명 → 게임 → 순위표
```

**2. 무엇이 왜 바뀌었고, 무엇이 좋아지나**

| 바뀐 것 | 왜 | 좋아지는 점 |
|---|---|---|
| 한 세트 **4문제 (피싱 2 + 정상 2)**, 기관용은 공통 3 + 직군 1 | 우리 체험자의 가장 큰 약점이 과잉 의심(1차 71%, 2차 54%)이라 정상을 2개 넣어야 제대로 잰다 | 과잉 의심 변화까지 잴 수 있고, 지금(최대 10문제)보다 짧다 |
| 사전·사후는 **쌍둥이 세트 A·B**, 사람마다 무작위 | 1·2회차 문제 난이도가 달라서 비교가 흔들렸다 (1·2차 한계) | "문제가 쉬워져서 오른 것 아닌가?"에 답할 수 있다 |
| **전원 사후 체험** (만점이어도) | 점수 낮은 사람만 다시 하면, 운이 나빠 틀린 사람이 저절로 올라 효과가 부풀려진다 | 교육성과(25점)의 근거인 전후 비교 숫자를 믿을 수 있다 |
| **실제 문자·메일 같은 화면** (교수님 제안) | 지금은 문제 카드처럼 보여서 "판단해야 한다"는 게 티가 난다 | 메일은 표시 이름만 보이고 눌러야 주소가 보여서, 실제처럼 어렵다 |
| **선택지 문구**: 세 개 모두 "확인한다", 확인하는 길만 다르게 + **순서 섞기** | 지금은 선택지 글자와 자리만 봐도 정답이 보인다 | 메시지를 읽어야만 풀 수 있다. 서버 값은 그대로라 서버·장부는 안 바뀐다 |
| **연쇄형은 연습 단계로** (첫 단계부터 평범하게) | 우리 작품의 특징(4유형 중 하나)인데, 지금은 단계마다 수상한 게 바로 보여 너무 쉽다 | 쌍둥이 짝 없이도 넣을 수 있고, 비교 통계와 섞이지 않는다 |
| **첫 화면 큰 버튼 3개** (C 제안) | 링크 검사·매뉴얼은 체험 뒤 궁금한 사람이 쓰는 기능 | 체험·게임에 집중되고, 결과 화면에서 바로 이어진다 |
| **작품 보안 점검** (C가 전해 준 피드백 반영) | 우리 서비스도 공격받을 수 있다: 점수 조작, 별명 칸 이상한 입력, 관리자 무단 접근, 장부 위변조 | 교육 기록·순위표를 믿을 수 있고, 작품 기술성이 올라간다 |
| **폰 기준** 화면 | 전시 관람객과 시범 운영 참여자 대부분이 폰으로 한다 | 접근성. PC에서는 가운데 폰 화면처럼 |

- 점검마다 4줄 기록: 무엇을 시도했나 / 왜 뚫렸나 / 어떻게 막았나 / 무엇을 배웠나

**5. 아직 의견 받는 것**

### 11/09 (A)

2·5·6·8번(화면 구조, 포스터, 시범 운영 측정, QR 대결)은 11/12 공지와 흐름 문서로 바뀌어서 지웠어요 (History에 있음).

**1. 방향 (A·B가 수업 때 이야기한 것)**
- 「내일의 솔루션」 제출 작업물을 그대로 이어 가되, **회사뿐 아니라 학생·일반인도 교육받을 수 있게** 업그레이드한다
- 기업 교육(실용성)은 그대로 살리고, 관람객도 즐길 수 있는 **게임을 추가**한다
- 지금 체험이 시험처럼 느껴지고 진부하다 → **실제로 메일·문자를 받은 것처럼** 생동감 있게 바꾼다

**3. 체험을 생동감 있게 (교수님 제안, 검토 중)**
- 진짜 메일·문자를 받은 것처럼 화면을 구성하고, 선택하면 **내 선택으로 무슨 일이 일어났는지 애니메이션으로 바로** 보여 주기
- 검토 의견: 결과 장면은 시나리오별이 아니라 **결과 유형별 템플릿**(돈 빠져나감 / 계정 탈취 / 앱 설치·정보 유출 / 막았음 / 정상 처리 / 업무 지연)으로 만들어 재사용. **정상 메시지를 멈췄을 때의 결과(업무 지연)도** 보여 줘야 과잉 의심이 늘지 않는다. 장면 뒤에는 꼭 해설
- B가 11/09 올린 **선택 미리보기**(아래 4번)가 이 방향의 첫 단계다

**7. 게임 (예시, 확정 아님)**
- 추천 3개: **카드 짝맞추기**(수법 ↔ 확인 방법, 교수님이 교육 효과가 가장 좋았다고 보여 준 방식) / **편지봉투 열기**(요구하는 행동 문구 → 악마·천사, 정상 봉투 포함) / **OX 퀴즈**(많이 틀린 유형 먼저, 속도 보너스는 자유 훈련 순위용)
- 문제 데이터는 2종류만: **메시지 문구 문제**(문구 + 피싱/정상 + 유형 + 이유 → 봉투·OX가 같이 씀) / **수법 ↔ 확인 방법 짝**(대응 매뉴얼에서 → 짝맞추기)
- 글자 조합, 가로세로 퍼즐, 타자 연습은 뒤로 (자세한 건 `docs/교내전시회_게임아이디어_참고.md`)
- 교육 효과는 게임 앞뒤 체험으로 재므로 게임 개수가 늘어도 측정은 그대로

**9. 보상 (아이디어, 경품 종류·기준 점수는 팀이 정함)**
- 관람객은 체험하고 바로 떠나므로, 최종 순위를 기다리지 않고 **그 자리에서** 준다
- **1등 경품:** 기준 점수 이상이면서 **현재 1위 기록을 깼을 때**. 동점이면 더 빨리 끝낸 사람. 경품이 부담되면 하루 단위로 1위 초기화
- **경품은 1인 1회**, 경품 대상 기록은 별명별 첫 판만 (다시 하는 건 자유)
- **참여 선물:** 사전 체험 → 게임 → 사후 체험을 **끝까지 한 사람**에게 (결과 화면을 부스에서 확인). 점수가 아니라 완료에 주므로 결과를 왜곡하지 않고, 교육 효과 데이터도 쌓인다

## 5. 약속과 설계 요약 (계속 쓰는 것)

### 결과지 양식 (JSON 6칸)

| 칸 | 뜻 |
|---|---|
| `type` | `url` 또는 `email` |
| `input` | 검사한 링크 주소 또는 메일 파일 이름 |
| `score` | 위험 점수 0~100. **반드시 `reasons`의 `points` 합계** |
| `model_probability` | AI 모델의 피싱 확률 0~1. 없으면 `null` |
| `reasons` | 이유 목록. 각각 `factor` / `points` / `text` |
| `unavailable` | 확인 못 한 항목 (`whois`, `spf`, `auth`). 0점 처리하지 않는다 |

### 탐지 엔진 배점

- **링크:** 도메인 유사 35 / 생성일 30일 미만 30 / 기관명 불일치 15 / 의심 키워드 10 / URL 구조 10. 생성일 조회 실패는 "확인하지 못한 항목"으로 표시. 판정 구간 60 이상 위험, 30 이상 주의
- **이메일:** DMARC 28 / SPF 17 / DKIM 0 / 표시 이름 위장 17 / 답장 주소 불일치 17 / 첨부 위험 11 / 압박 문구 10. 헤더에 적힌 인증 결과(`auth_results`)를 읽어 점수로 바꾼다. DKIM 0점 이유: 정상 메일도 서명이 자주 깨져 오탐이 나기 때문. 카드에 `dkim=fail`은 쓰지 않는다
- 문자 해설에는 본문 압박 문구를 따로 보여 주고, 링크 점수에는 넣지 않는다
- 새 시나리오를 만들면 링크를 `/check`에 넣어 점수를 확인한다

### AI 모델 (URL 피싱 확률)

- **데이터:** PhiUSIIL Phishing URL (UCI 967, Arvind Prasad·Shalini Chandra 2024, DOI https://doi.org/10.1016/j.cose.2023.103545, CC BY 4.0). 저장소에 올리지 않는다
- **모델:** 주소 모양 특징 9개, 로지스틱 회귀 (Colab 학습, 서버에는 숫자만 `url_model.json`)
- **성능 (시험용 47,159개):** 정확도 76.5%, 정밀도 94%, 재현율 48%
- **쓰는 방법:** 위험 점수에 더하지 않고, 피싱 확률 60% 이상일 때만 참고 표시. 아래는 "주소 모양만으로는 구별하기 어려워요"
- 특징·단어 목록을 바꾸면 노트북에서 다시 학습하고 `url_model.json`도 바꿔야 한다

### 장부 약속 (A, 바꾸면 기록 검사가 틀어짐)

- 사이트에서 쓰는 것: `ledger_v2.py`·`hashchain_v2.py`. 고치면 바로 기록 저장이 바뀐다. Colab SQLite로 먼저 시험한다
- 테이블 `ledger(seq, prev_hash, record, created_at, hash)`. `record`와 `created_at`은 **글자** 그대로 저장
- 지문 = SHA-256 (환경 변수 `HASH_SECRET`이 있으면 HMAC-SHA256). 첫 기록의 `prev_hash`는 `"0"` 64개
- `ledger_head` 표로 **끝 기록 삭제**도 잡는다. **장부를 비울 때는 `ledger`와 `ledger_head`를 둘 다** 비운다. 열쇠를 바꾸면 그 전 기록은 전부 "변조"로 나온다
- 해시체인은 변조를 **막는 것이 아니라 들키게 하는 것** → "위변조 탐지·검증"이라고 쓴다
- 알려진 한계: 열쇠 노출 시 보호가 약해짐, DB와 Vercel 설정을 둘 다 가진 사람은 못 막음, 저장 실패한 기록은 장부에서 빠짐
- **장부 한 줄:** `anon_id`, `job`, `self_check`, `scenario_id`, `case_type`, `is_phishing`, `choice`, `is_correct`, `over_suspicion`, `analysis` (+ 2회차 `round`, 연쇄형 `stopped_step`)
- **새로 넣을 칸 (11/12, 이름은 A가 서버 만들 때 정해서 칸 이름 사전에 추가):** 개인용/기관용, 세트 A·B, 대상, 해 본 적 있는지, 연쇄형 연습 표시. 넣은 뒤 [기록 검사]가 그대로 "이상 없음"인지 확인
- **게임 점수는 장부에 넣지 않는다** (따로 저장)

| 시나리오 | `click` 메시지가 시키는 대로 바로 처리 | `call` 메시지가 알려 준 연락처로 문의 | `official` 멈추고 따로 확인 |
|---|---|---|---|

### 새 시나리오 카드를 쓸 때 (B)

## 7. 지금 유효한 팀 결정 (자세한 기록은 이 파일 History)

**AI는 이 목록을 다른 초안보다 우선한다.**

1. 저장소 공개, `main`에 바로 저장, Vercel 배포, 외부 PostgreSQL(Neon). 비밀 정보는 Vercel 환경 변수에만
2. 관리자는 지금 회사 코드로 입장 → 교내 경진대회에서 **관리자 비밀번호를 따로** 두고, 틀린 시도 반복을 막는다 (11/12)
3. **사전·사후 각 4문제 (피싱 2 + 정상 2)**, 쌍둥이 세트 A·B를 사람마다 무작위. 기관용은 공통 3 + 직군 1. 카드 순서는 서버가 섞음 (11/12)
4. 제한 시간 문자 15초, 메일 25초. 시간이 지나도 고를 수 있고, 시간 안에 못 고른 수만 결과에 표시 (기관용 조정 검토)
5. 문진표는 체험 앞 (자신감과 실제를 비교하려고). 체험 시작 안내에는 정답 힌트("보낸 곳을 보세요" 등)를 넣지 않음
6. 메시지에 없는 수단의 선택지는 같은 뜻의 행동으로 바꿈 (번호 없는 메일의 전화 → 답장)
7. 속은 순간은 화면 전체 경고 대신 단서 번호와 "실제였다면" 한 줄 (회사 교육에서 놀라게 하지 않음)
8. 결과는 두 점수. **만점이어도 전원 사후 체험** (11/12). 기관용은 해설 뒤 따라 쓰기, 개인용은 게임 훈련
9. 다시 도전 효과는 처음 해 보는 사람의 기록으로만 말한다. 이미 해 본 사람에게 예전 선택을 따라 하게 부탁하지 않는다 (허위·조작 방지)
10. 뱃지·레벨(보안 대응 수준 등): 「내일의 솔루션」 때는 회사 교육 취지에 맞지 않아 뺐음. 교내 경진대회에서는 다시 고려해도 됨 (A 11/09)
11. 대응 매뉴얼 공식 자료는 B 초안과 섞지 않고 별도 상자, 출처 표기, 특정 회사 전용 안내는 넣지 않음
12. 화면 표현: "실제 업무 환경과 비슷하게 만든 가상 화면 (특정 서비스의 로고·이름·디자인을 쓰지 않음)"
13. 시범 운영 숫자는 마감 시각 캡처 기준만 쓴다
14. 첫 화면은 큰 버튼 3개(개인용 / 기관용 / 자유 훈련). 링크 검사·대응 매뉴얼은 메뉴·사이드 바와 결과 화면 [더 알아보기] (C 제안, 11/12)
15. 연쇄형은 사전·사후 사이 연습 단계. 연습 기록은 비교 통계에서 뺀다 (11/12)
16. 게임 점수는 장부·교육 통계와 섞지 않는다. 순위표 점수는 서버가 계산 (11/12)
17. 작품 보안 점검은 우리 서비스에만, 장부는 테스트용 복사본에서만 (11/12)
