## 1. 이 함수가 하는 일

사전 체험(1회차)과 사후 체험(2회차)을 **둘 다 한 사람만** 모아서, 두 점수가 어떻게 바뀌었는지 계산해요. 관리자 화면의 "전후 비교" 숫자가 이걸로 나와요.

- **막은 피싱** = 피싱 기록 중 `is_correct`가 `true`인 비율
- **처리한 업무** = 정상 기록 중 `over_suspicion`이 `false`인 비율
- 비율은 사람마다 따로가 아니라, 그 묶음 사람들의 답을 **모두 합쳐서** 계산
- 서버의 `retry_effect`(지금 다시 도전 비교)와 같은 방식이에요. 참고해도 돼요

## 2. 받는 것

`compute_prepost(entries, min_group=3)`

- `entries`: 장부 기록 목록. 하나는 `{"record": {...}}` 모양 (`compute_stats`와 같음)
- `min_group`: 묶음 인원이 이보다 적으면 그 묶음은 숨김 (기본 3명, 한 사람 결과가 드러나지 않게)

`record`에서 쓰는 칸 (11/13 정한 이름, A가 서버에서 이 이름으로 저장):

| 칸 | 값 | 뜻 |
|---|---|---|
| `anon_id` | `U00000A` 같은 문자 | 익명 번호 |
| `round` | `1` / `2` (없으면 1) | **1 = 사전, 2 = 사후** |
| `is_phishing` | `true` / `false` | 피싱 카드였나 |
| `is_correct` | `true` / `false` | 피싱을 막았나 (피싱 카드에서만 씀) |
| `over_suspicion` | `true` / `false` | 정상인데 멈췄나 (정상 카드에서만 씀) |
| `mode` | `personal` / `org` | 개인용 / 기관용 (새 칸) |
| `target` | `student` / `general` / `worker` | 학생 / 일반인 / 직장인 (새 칸) |
| `revisit` | `true` / `false` | 캐치피싱을 해 본 적 있나 (새 칸) |
| `practice` | `true` (연습일 때만 있음) | 연쇄형 연습 기록 → **계산에서 빼기** (새 칸) |

규칙:
- `practice`가 `true`인 기록은 빼기
- 사전만 하고 그만둔 사람(2회차 기록 없음)은 빼기
- 칸이 빠진 이상한 기록이 있어도 멈추지 말고 건너뛰기 (`compute_stats`의 `_records`처럼)
- 기록이 없어서 못 구하는 비율은 `0`이 아니라 `None`, 소수점 셋째 자리까지 (`_rate` 그대로 써도 돼요)

## 3. 돌려줄 것

```python
{
  "people": 3,                         # 사전·사후 둘 다 한 사람 수
  "all": {                             # 전체 (인원이 적어도 항상 보여 줌)
    "people": 3,
    "pre":  {"phishing_blocked": 0.5,   "normal_handled": 0.5},
    "post": {"phishing_blocked": 0.833, "normal_handled": 0.667}
  },
  "by_mode":    {"personal": {...같은 모양}, "org": {...}},
  "by_target":  {"student": {...}, "general": {...}, "worker": {...}},
  "by_revisit": {"first": {...}, "again": {...}}   # revisit false → first, true → again
}
```

- `by_...` 안의 묶음은 인원이 `min_group`보다 적으면 **아예 빼요** (빈 `{}`일 수 있음)
- 값이 `None`인 묶음(예: `target`이 없는 옛 기록)은 묶음에서 빼요

## 4. 시험용 가짜 기록과 손계산 정답

가짜 기록: `docs/양식/C_샘플기록.json` (27줄)

| 사람 | mode | target | revisit | 사전 (피싱 2 / 정상 2) | 사후 (피싱 2 / 정상 2) |
|---|---|---|---|---|---|
| U00000A | personal | student | false | 막음 1/2, 처리 1/2 | 막음 2/2, 처리 2/2 |
| U00000B | personal | general | true | 막음 0/2, 처리 2/2 | 막음 1/2, 처리 1/2 |
| U00000C | org | worker | false | 막음 2/2, 처리 0/2 | 막음 2/2, 처리 1/2 |
| U00000D | personal | student | false | 사전만 하고 그만둠 → **빠짐** | 없음 |

그리고 U00000A에게 연쇄형 연습 기록 1개(`practice: true`)가 있어요 → **빠짐**

**손계산 (전체 3명)**
- 사전 막은 피싱 = (1 + 0 + 2) / (2 + 2 + 2) = 3/6 = **0.5**
- 사전 처리한 업무 = (1 + 2 + 0) / 6 = 3/6 = **0.5**
- 사후 막은 피싱 = (2 + 1 + 2) / 6 = 5/6 = **0.833**
- 사후 처리한 업무 = (2 + 1 + 1) / 6 = 4/6 = **0.667**

**손계산 (묶음, `min_group=1`로 시험할 때)**
- `by_mode.personal` (A, B 2명): 사전 막음 1/4 = 0.25, 처리 3/4 = 0.75 / 사후 막음 3/4 = 0.75, 처리 3/4 = 0.75
- `by_mode.org` (C 1명): 사전 막음 1.0, 처리 0.0 / 사후 막음 1.0, 처리 0.5
- `by_revisit.first` (A, C 2명): 사전 막음 3/4 = 0.75, 처리 1/4 = 0.25 / 사후 막음 4/4 = 1.0, 처리 3/4 = 0.75
- `by_revisit.again` (B 1명): 사전 막음 0.0, 처리 1.0 / 사후 막음 0.5, 처리 0.5
- `by_target`: student(A) 사전 0.5·0.5 / 사후 1.0·1.0, general(B) 사전 0.0·1.0 / 사후 0.5·0.5, worker(C) 사전 1.0·0.0 / 사후 1.0·0.5

**`min_group=3`(기본)으로 하면** 묶음은 전부 3명 미만이라 `by_mode`·`by_target`·`by_revisit`가 모두 `{}`, `all`만 위 숫자
