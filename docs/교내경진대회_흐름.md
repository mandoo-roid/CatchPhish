## 1. 체험자 입장

### 첫 화면

큰 버튼 세 개: **[개인용 체험] [기관용 체험] [자유 훈련]**
링크 검사와 대응 매뉴얼은 위쪽 메뉴(☰) 안에 있고, 컴퓨터에서는 사이드 바에 보여요. (C 제안, 11/11)

### [개인용 체험] (학생·일반인)

1. **사전질문:** 학생인지 일반인인지, 캐치피싱을 해 본 적 있는지, 피싱을 알아볼 자신이 있는지
2. **문자·메일 4개 도착:** 실제 문자 앱, 메일 앱처럼 생긴 화면으로 하나씩 와요
3. **행동 고르기:** 선택지 세 개가 모두 "확인한다"처럼 보여서, 메시지를 읽어야만 고를 수 있어요
4. **선택 미리보기 → 해설:** 고른 행동이 어떻게 되는지 잠깐 보여 주고, 무엇을 봤어야 했는지 알려 줘요
5. **연쇄형 체험:** 처음엔 평범했던 연락이 점점 수상한 부탁을 해요. 어디서 멈출지 골라요 (연습이라 점수에 안 들어가요)
6. **게임 훈련:** 행동 문구 블록 중 위험한 행동만 골라 눌러요 (아래 6번 "게임")
7. **문자·메일 4개 다시 도착:** 처음 보는 새 문제예요
8. **결과:** 사전과 사후 두 점수를 나란히 보여 줘요
   - **막은 피싱:** 피싱을 잘 멈췄나
   - **처리한 업무:** 정상 메시지까지 의심하지 않고 잘 처리했나
   - 보안 대응 수준, 맨 아래 **[더 알아보기: 링크 검사 / 대응 매뉴얼]**

### [기관용 체험] (회사·기관 직원)

1. **기관 코드 입력**
2. **직군 선택:** 인사, 재무, 영업, 개발, 일반 사무
3. **사전질문**
4. **문자·메일 4개:** 공통 문제 3개 + 내 직군에게만 오는 문제 1개
5. **해설 → 대응 매뉴얼 문장 따라 쓰기**
6. **연쇄형 체험** (연습)
7. **문자·메일 4개 다시 도착** (처음 보는 문제, 게임 없음)
8. **결과:** 두 점수 전후 비교, 맨 아래 [더 알아보기]

### [자유 훈련] (누구나)

1. 별명 정하기
2. 체험 없이 바로 게임 **"생활 속 피싱 신호 익히기"** (아래 6번 "게임")
3. 점수가 순위표에 올라가요

## 2. 푸는 문제

- **한 세트 4문제: 피싱 2 + 정상 2.** 우리 체험자의 가장 큰 약점이 과잉 의심(1차 71%, 2차 54%)이라 정상도 2개 넣어야 제대로 잰다
- **기관용 구성:** 직군 카드 1개는 피싱(지금 직군 카드 5개가 모두 피싱), 공통 3개는 피싱 1 + 정상 2

> **⚠️ 쌍둥이 카드: 세트 A와 B의 짝은 난이도가 최대한 같아야 한다.** 다르면 사전·사후 차이가 학습 효과인지 문제 차이인지 알 수 없다.
> - 같은 유형 (기관 사칭이면 둘 다 기관 사칭), 같은 종류 (문자/메일)
> - 단서 개수가 같게 (A에 이상한 점이 2개면 B도 2개)
> - 비슷한 길이
> - 탐지 엔진 점수가 비슷한 구간
> - 다 쓰면 짝끼리 나란히 놓고 "어느 쪽이 더 쉬운가?" 서로 확인

사전(세트 A)과 사후(세트 B)는 **모양이 같은 쌍둥이 문제**예요. 그래야 실력이 늘었는지 공정하게 잴 수 있어요. 사람마다 A와 B 중 무엇을 먼저 볼지는 무작위예요.

- 소재는 예시. 쌍둥이 규칙만 지키면 바꿔도 됨

## 3. 문제를 어렵게 만드는 방법

지금 문제가 쉬운 이유: **문제 카드처럼 보여서 "판단해야 한다"는 게 티가 나고, 보낸 곳이나 선택지 글자만 봐도 정답이 보인다. 정답 선택지도 늘 같은 자리다.**

### ① 진짜 문자·메일 화면 (교수님 제안, 1순위)
- 메일은 진짜 앱처럼 **표시 이름만 보이고, 실제 주소는 눌러야 보이게** → 표시 이름 위장이 실제처럼 통한다
- 문자는 말풍선, 보낸 번호, 링크가 실제 문자처럼
- 억지로 어렵게 만든 게 아니라 **현실과 같아서 어려운 것**
- 특정 서비스의 로고·이름·디자인은 쓰지 않는다 (팀 결정 12번)
- 문자 화면 1개 + 메일 화면 1개 **틀만 만들고, 시나리오는 데이터로 갈아 끼운다**

### ② 메시지
- 보낸 곳과 요구가 어긋나게: 회사 주소처럼 보이는 피싱, 바깥 주소인 정상
- 지금은 피싱 문자가 모두 010, 정상은 회사 번호 → 섞기 (가짜 번호만)
- 정상 메시지에도 "오늘까지" 같은 급한 말 → 압박 문구만으로 판단 못 하게
- 판단 기준은 끝까지 **"요구하는 행동"과 "확인 경로"**. 단서는 반드시 본문 안에
- AI가 쓴 듯한 문체 다듬기

### ③ 선택지: 세 개 모두 "확인한다", 확인하는 길만 다르게

예시 문자: "[학사지원팀] 2학기 장학금 지급 계좌 확인이 필요합니다. 오늘 18시까지 아래 링크에서 계좌 정보를 다시 입력해 주세요."

| 값 | 지금 방식 (정답이 보임) | 바꾼 방식 |
|---|---|---|
| `click` | 링크를 누른다 | 링크로 들어가 학사지원팀 공지가 맞는지 확인한다 |
| `call` | 문자 속 번호로 전화한다 | 문자에 적힌 번호로 전화해 진짜 학사지원팀인지 확인한다 |
| `official` | 멈추고 따로 확인한다 | 학교 포털 앱을 열어 장학금 공지가 있는지 확인한다 |

- 사람들은 링크를 누를 때도 "확인하려고" 누른다 → 더 현실적이고, **"확인 경로가 어디인가"**를 정확히 묻는다
- 정상 메시지에서 늘 포털만 고르면 처리한 업무 점수가 떨어지니 "무조건 포털"로도 못 이긴다
- 세 문장 길이 비슷하게
- **화면에서 선택지 순서 섞기.** 서버 값(`click`/`call`/`official`)은 그대로라 서버·장부는 안 바뀐다

### ④ 확인
- 링크는 `/check`, 메일은 이메일 엔진에 넣어 점수 확인
- 다 만든 뒤 팀원끼리 서로 풀어 보고 너무 쉽거나 억지스러운 카드 고치기

## 4. 연쇄형 (연습 단계)

- 「내일의 솔루션」 자료조사 때 정한 4유형 중 하나이고, 1차 때 많이 속은 유형(8회)이라 **우리 작품의 특징** → 뺄 수 없다
- 지금 연쇄형은 단계마다 수상한 게 바로 보여서 너무 쉽다 → **크게 개선해서 학습 단계에 넣는다** (제안)
- 개선 방향: 첫 연락은 링크도 요구도 없이 평범하게 (신뢰 쌓기) / 요구는 작은 것부터 점점 크게 / 진짜 같은 화면으로
- 학습 단계에 두면 쌍둥이 짝이 필요 없고, 기관용(해설만이라 학습이 약했음)에도 훈련 내용이 생긴다
- 학습 단계 연쇄형 기록은 **사전·사후 비교 통계에서 뺀다**

## 5. 모바일

- 전시 관람객과 시범 운영 참여자 대부분이 **폰으로 한다.** 지금은 PC 기준이라 폰에 맞춰야 한다
- 진짜 문자·메일 화면은 원래 폰 모양이라 **폰 기준으로 만들고, PC에서는 가운데에 폰 화면처럼** 보여 준다
- 볼 것: 글자·버튼 크기, 해설 길이, 따라 쓰기(폰에서 긴 문장 치기 힘듦), 제한 시간, 게임 카드 크기
- 관리자 화면은 담당자가 PC로 보니까 우선순위 낮음
- 검수 때 **실제 폰(아이폰·안드로이드)으로** 확인

## 6. 개발자 입장

### 첫 화면

- 큰 버튼 3개로 바꾸고, 링크 검사·대응 매뉴얼은 메뉴(☰)와 사이드 바로
- 개인용은 `game.html?mode=personal`, 기관용은 `game.html?mode=org`, 자유 훈련은 게임 화면으로. 주소 끝 꼬리표로 어느 길인지 알려 줌

### 문제 파일 (`scenarios/scenarios.json`)

카드마다 이름표 추가

- `audience`: 개인용 / 기관용
- `set`: A / B
- `pair`: 쌍둥이 번호 (A의 1번과 B의 1번이 같은 번호)
- 연쇄형 S06에는 연습용 표시

### 서버 (`api/`)

지금 있는 "1회차 → 다시 도전 2회차" 구조를 **사전 → 사후**로 그대로 씀. 새로 짜는 게 아니라 규칙을 바꾸는 것.

1. **시작:** 화면이 개인용·기관용, 대상을 보내면 서버가 세트 A나 B를 무작위로 골라 4문제를 줌. 기관용은 공통 3 + 그 직군 카드 1
2. **사후:** "만점이 아니면 다시 도전" → **모두 사후 체험**, 처음과 **반대 세트**
3. **연쇄형:** 사전과 사후 사이에 따로 주고, 장부에 연습 표시를 해서 비교 통계에서 뺌
4. **장부 새 칸:** 개인용/기관용, 세트, 대상, 해 본 적 있는지. 넣은 뒤 [기록 검사]가 그대로 "이상 없음"인지 확인

### 체험 화면 (`game.html`)

1. 기관용일 때만 직군 화면
2. 사전질문에 대상, 해 본 적 있는지 추가
3. **실제 같은 화면 틀 2개:** 문자 앱 1개, 메일 앱 1개. 카드 내용만 갈아 끼움. 메일은 보낸 사람 이름만 보이고, 누르면 주소가 보이게
4. **선택지 순서 섞기:** 보이는 순서만 섞고, 서버로 보내는 값(`click`/`call`/`official`)은 그대로
5. 개인용은 연쇄형 다음에 게임, 기관용은 따라 쓰기
6. **결과 화면:** 사전·사후 두 점수 나란히, 맨 아래 [더 알아보기]
7. **모바일:** 폰 기준으로 만들고, 컴퓨터에서는 가운데 폰 화면처럼

### 게임 (틀 하나, 문제 두 종류)

**출처:** 한컴타자연습 「워드 크러시 사가」의 블록 판 방식을 참고 (C 제안). 전시 관람객이 폰으로 하므로 타자 입력 대신 누르기로 바꾸고, 생활 문자 신호·같은 보낸 곳 짝·수법 뱃지·즉시 피드백·다시 출제로 발전시킴 (A). 게임 이름과 만든 곳 표기는 확인 필요. **방식만 참고하고 디자인·이름·그림은 따라 하지 않는다.** 시안: `docs/game_draft.html` (링크: https://mandoo-roid.github.io/CatchPhish/game_draft.html, GitHub Pages)

**공통 틀:** 블록 판 + 콤보 + 위험한 것만 누르기. 맞히면 터지고, 정상을 누르면 감점 + 콤보 끊김 + 그 자리에서 이유

| | 자유 훈련: 생활 속 피싱 신호 익히기 | 개인용 체험 중간 |
|---|---|---|
| 블록 | **문자 알림 카드** (보낸 곳 + 한 줄 내용), 2열 8장 | **행동 문구** (예: 문자 속 번호로 문의 ↔ 대표번호 찾아서 문의) |
| 누르면 맞음 | 피싱 문자 → 맞히면 "스미싱!", "큐싱!" 같은 **수법 이름 뱃지** | 위험한 행동 |
| 함정 | 같은 보낸 곳의 정상 문자 (예: 카드사 · 결제 완료, 자세한 건 카드 앱에서) | 안전한 행동 |
| 시간 | 60초, 20초마다 1·2·3단계로 어려워짐 (3단계는 같은 보낸 곳 짝 위주) | **시간 제한 없음**, 위험한 행동을 다 찾으면 끝 (팀 결정: 게임은 속도보다 정확성, 속도는 자유 훈련 순위용) |
| 놓침 | 피싱 카드를 8초 동안 안 누르면 "놓쳤어요" | 없음 |
| 다시 출제 | 틀린 정상 문자가 약 12초 뒤 다시 나옴 → 이번에 안 누르면 맞힘 | 같은 방식 |
| 끝나고 | 점수, 잡은 피싱, 놓친 피싱, 정확도, 다시 나온 문자 맞힌 수, 오늘 배운 것 3개, 잡은 수법, 판단 기준 한 줄, 순위표 | 판단 기준 한 줄 → 바로 사후 체험 |
| 순위표 | 있음 | 없음 |
| 문제 데이터 | **C** (아래 칸) | 새 시나리오 선택지 문구에서 **A**가 뽑음 |

**자유 훈련 문제 데이터 칸 (C):** 보낸 곳 / 내용 / 피싱 여부 / 난이도(1·2·3) / 이유 한 줄 / 수법 이름(피싱만) / 출처
- **40개 이상** (반복되면 외워서 순위가 갈림)
- 피싱·정상 짝은 **보낸 곳이 같게** (이 게임의 핵심)
- 위험 쪽은 공식 자료(경찰청·금융감독원·KISA 등)에 나온 수법만, **애매한 것은 빼고, 출처 없는 것은 넣지 않기**
- 기관 이름은 써도 되지만 로고·디자인은 쓰지 않기 (결정 12번)

**교육 효과 (작품 설명서에서 무게):** 교육 효과의 주된 근거는 체험 전후 비교. 자유 훈련은 **보조 근거**로 "다시 나온 문자 정답률", 단계별 정확도, 많이 헷갈린 문자(예: [Web발신]을 피싱으로 착각한 비율)를 게임 기록에 익명으로 모아 씀. 며칠 뒤 효과는 재지 못한다고 정직하게

**저장과 순위표**
1. **게임 점수와 측정값은 체험 장부와 따로** 저장. 해시체인과 교육 통계를 건드리지 않게
2. **순위표:** 점수는 서버가 직접 계산(서버가 판을 내주고, 누른 카드 목록을 받아 다시 채점), 별명은 길이·글자 검사, 같은 기록 반복 등록 막기

### 관리자 화면 (`frontend/admin.html`, `stats.py`)

1. 새 통계: 사전·사후 비교, 대상별, 해 본 적 있는지별 (계산 함수 C, 연결 A)
2. **관리자 비밀번호를 회사 코드와 따로** 두고, 틀린 시도 반복을 막음. 화면뿐 아니라 관리자 데이터 주소도 잠금

### 작품 보안 점검 (공격 → 막기 → 다시 공격)

| 점검 | 공격 | 막기 |
|---|---|---|
| 점수 조작 | 순위표에 조작한 점수 보내기 (A) | 서버가 점수 계산 (A) |
| 장부 위변조 | 테스트용 복사본에서 기록 고치기·지우기·끼워 넣기 (A) | [기록 검사]가 잡는지 확인, 한계 정리 (A) |
| 관리자 무단 접근 | 관리자 주소·데이터 주소에 코드 없이, 틀린 코드로 반복 접근 (C, 막기 전·후) | 관리자 비밀번호 따로 + 틀린 시도 반복 막기 (A) |
| 별명 칸 입력 | 별명 칸에 스크립트 넣기 (C, 막기 전·후) | 입력 검사, 글자 그대로 표시 (A) |

- 공격은 **우리 서비스에만**, 장부는 **테스트용 복사본에서만**
- 점검마다 4줄 기록: 무엇을 시도했나 / 왜 뚫렸나 / 어떻게 막았나 / 무엇을 배웠나
- 막기 전·후 화면 캡처

## 8. 이렇게 하는 이유

- **교육성과 중심:** 모든 길이 "처음 → 배우기 → 다시"로 끝나서, 교육성과(25점)의 근거인 전후 비교가 흐름의 중심
- **공정한 비교:** 쌍둥이 세트 + 무작위 순서 + 전원 사후 체험. "문제가 쉬워져서 오른 것 아닌가?"에 답할 수 있고, 1·2차 시범 운영 한계(표본, 1·2회차 난이도 차이, 결과 화면 긺)를 고친 근거
- **과잉 의심까지:** 정상 2개라 과잉 의심 변화를 제대로 잴 수 있음
- **실제처럼:** 실제 문자·메일 같은 화면 + 정답이 보이지 않는 선택지라, 시험이 아니라 실제 판단을 하게 됨 (교수님 제안)
- **작업량 줄이기:** 이미 있는 "1회차 → 2회차" 구조를 그대로 써서 서버를 새로 짜지 않음. 개인용·기관용 뼈대가 같음
- **짧게:** 지금 최대 10문제 → 8문제
- **믿을 수 있는 서비스:** 원래 해시체인으로 하던 기록 위변조 탐지를 보안 점검으로 보완해서, 교육 기록과 순위표까지 지킴 (기술성)
- **대상 확장:** 개인용과 자유 훈련으로 학생·일반인까지 넓힘 (심사 2번 지역사회, 6번 확산)
- **첫 화면 정리:** 체험·게임에 집중하고, 부가 기능은 체험이 끝난 자리에서 이어짐 (C 제안)
- **게임 점수는 장부 밖:** 해시체인과 교육 통계가 깨지지 않음
- **게임 (C 제안 → A 발전):** 같은 보낸 곳 짝이라 단어가 아니라 "무엇을 하라는지"를 읽어야 맞힘. 우리 체험 판단 기준 그대로이고, 수법 이름은 실제 상황과 짝지어 배움. 틀 하나에 문제만 바꿔 작업량이 적음

## 9. 걱정되는 점

- **새 시나리오 부담:** 개인용 8개 + 새 직군 카드 5개 + 기존 카드 손보기 + 연쇄형 첫 단계. 가장 큰 위험
- 화면 작업이 늘어남 (실제 같은 화면 + 모바일)
- 쌍둥이로 만들어도 세트 A·B 난이도가 완전히 같지는 않음 → 시범 운영 뒤 카드별 정답률을 보고 차이가 크면 정직하게 적기
- 기관용 참여자가 적으면 기관용 숫자는 몇 건 안 나올 수 있음
- 개인용은 해설 + 게임이 함께라 게임 하나의 효과만 따로 증명하기 어려움 → "해설 + 게임 훈련 뒤 전후 변화"로 말하기
- 짧은 훈련이라 변화가 작을 수 있음. 막은 피싱은 이미 높음 (다시 도전 8명 규모의 시범 결과 83% → 83%)
- 사후 체험에서 일부러 다 의심할 수 있음 (두 점수에 드러나긴 함)
- 직군 카드가 늘 피싱이면 눈치 빠른 사람은 알아챌 수 있음 (한 사람이 2개만 봐서 크진 않음)
- 문제를 어렵게 하다 억지스러워질 수 있음
- 게임 카드는 짧은 문구라 실제 문자의 맥락을 다 담지 못함 → 맥락 판단은 체험이 맡고, 게임은 "신호 익히기". 결과 화면에 판단 기준 한 줄
- 게임 데이터가 틀리면 잘못 가르침, 적으면 외워서 순위가 갈림 → 출처 필수, 40개 이상
