# 학교 공식 메일 도메인 목록

> B 작성 (11/15). 학생용 시나리오의 "표시 이름 위장"을 이메일 엔진이 알아보게 할 때 쓰는 목록이에요. 엔진 반영은 A 담당 (`docs/해설_엔진문장_검토.md` 2-3).
> **B가 직접 확인한 것만** 적어요. 짐작으로 적으면 엔진이 진짜 학교 메일을 의심하게 될 수 있어요.

## 1. 확인한 것

| 구분 | 값 | 확인 방법 |
|---|---|---|
| 학교 공식 메일 도메인 | `baewha.ac.kr` | B 확인 (학교 메일 주소 `@baewha.ac.kr`) |
| 학교 학습관리시스템(LMS) | 클라썸 (외부 서비스) | B 확인 (수업에서 사용) |
| 클라썸 알림 메일 도메인 | `classum.com` | B 확인 (받은 클라썸 알림 메일의 보낸 주소 `@classum.com`) |

## 2. 아직 확인이 필요한 것

| 항목 | 왜 필요한가 | 확인 방법 |
|---|---|---|
| 학교 포털 주소 | 시나리오의 "학교 포털에 직접 접속" 안내와 맞추려고 | 평소 접속하는 포털 주소창에서 그대로 적기 |
| 학과·부서가 다른 도메인을 쓰는지 | 같은 학교인데 다른 주소면 목록에 같이 넣어야 함 | 학과 사무실·학사지원팀에서 받은 메일 보낸 주소 확인 |

## 3. 엔진에 넣는다면 (A에게 제안, 팀 논의)

- 학교 도메인 목록: `baewha.ac.kr`, `classum.com` (클라썸은 학교 바깥 서비스지만 학교 수업 알림을 보내는 주소라 함께 넣어야 진짜 알림을 의심하지 않음)
- 학교처럼 보이는 표시 이름 낱말 예: "대학교", "학사", "포털", "학과", "클라썸"
- 규칙: 표시 이름에 학교 낱말이 있는데 보낸 주소가 목록에 없으면 "표시 이름 위장" (회사 부서 이름을 볼 때와 같은 방식)
- 결과 예상: 개인용 P02(학교 포털)·P06(학교 클라우드)이 0점 → 17점으로 같이 올라 쌍둥이 점수는 그대로

## 4. 시나리오 카드에는 실제 도메인을 쓰지 않아요

- 카드 속 주소는 지금처럼 가상의 `univ.example`(진짜 학교 자리)과 `univ-portal-notice.example` 같은 가짜 주소를 써요 (팀 규칙: 연습용 주소는 `.example`)
- 실제 학교 주소와 비슷하게 꾸민 피싱 주소를 만들면 진짜 학교를 사칭하는 모양이 되므로 쓰지 않아요
- 그래서 엔진 시험용으로는 `univ.example`을 "학교 도메인" 자리에 함께 넣어야 카드에서 동작을 확인할 수 있어요 (A가 넣을 때 참고)
- 실제 서비스 이름(클라썸)도 카드 속 피싱 메일의 보낸 곳으로는 쓰지 않아요. 정상 카드는 지금처럼 "학습관리시스템(LMS)"으로 둬요 (팀 논의: 정상 카드에 실제 이름을 넣어 더 실감 나게 할지)
