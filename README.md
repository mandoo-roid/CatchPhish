# Phish&Chips · 캐치피싱(CatchPhish)

AI 기반 피싱 탐지 및 보안 교육 체험 플랫폼 (캡스톤디자인)

## 이 저장소는 무엇인가요?

팀원 3명(보안 A, B, C)이 **코드를 한곳에 모아 두는 보관함**입니다.
GitHub에 올린다고 웹사이트가 바로 열리지는 않고, 코드를 받아서 서버를 켜야 실행됩니다.

아직 없는 폴더는 **처음 파일을 올릴 때 만들어집니다.**

| 폴더 | 들어가는 것 | 담당 |
|---|---|---|
| `samples/` | 결과 모양 샘플 (JSON 파일 3개) | A |
| `backend/url_analyzer/` | 링크 점수 함수, Colab 연습 노트북(`url_practice.ipynb`) | A |
| `backend/email_analyzer/` | 이메일 헤더 분석, Colab 연습 노트북(`email_practice.ipynb`) | B |
| `backend/db_logs/` | 장부(DB), 해시체인, 통계 | C |

맨 바깥의 `.gitignore`는 **GitHub에 올리면 안 되는 파일 목록**입니다 (예: 비밀번호가 담긴 `.env`).

**규칙: 자기 폴더의 파일만 고칩니다.** 다른 사람 폴더에서 고칠 게 보이면 직접 고치지 말고 단톡에 알려 주세요.

## 결과 형식 (samples/ 폴더)

링크든 이메일이든, 분석이 끝나면 **아래 칸 이름으로 결과를 만들어서 넘기자**는 약속입니다.
이어달리기의 바통 모양을 똑같이 맞추는 것과 같습니다.

```
A(링크 분석) ─┐
              ├─ 결과 ──→ B가 화면에 보여줌
B(이메일 분석)─┘        └→ C가 장부에 저장
```

### 칸 설명

| 칸 | 쉬운 뜻 | 만드는 사람 | 쓰는 사람 |
|---|---|---|---|
| `type` | 링크 검사인지 이메일 검사인지 (`url` 또는 `email`) | A, B | B, C |
| `input` | 검사한 것 자체 (링크 주소 또는 메일 파일 이름) | A, B | B, C |
| `score` | 위험 점수 (0~100) | A, B | B, C |
| `model_probability` | AI 모델이 말한 피싱 확률 (0~1). 모델이 없으면 `null` | A | B, C |
| `reasons` | 점수가 나온 이유 목록 | A, B | B (화면), C (저장) |
| `unavailable` | 확인하지 못한 항목의 짧은 이름 목록. 없으면 빈 목록 `[]` | A, B | B, C |

`unavailable`에 쓰는 이름은 코드와 똑같이 맞춥니다: 도메인 생성일 조회 실패 `whois`, 메일 검사 결과 없음 `spf`.

### reasons 안의 칸

| 칸 | 쉬운 뜻 | 예시 |
|---|---|---|
| `factor` | 이유의 이름 | 도메인 유사 |
| `points` | 이 이유로 더해진 점수 | 35 |
| `text` | 사람이 읽는 설명 문장 | 유명 이름과 비슷하지만 똑같지는 않은 도메인입니다. |

## 샘플 3개

| 파일 | 점수 | 이유 | 보여주는 것 | 만든 방법 |
|---|---|---|---|---|
| `url_dangerous.json` | 75 | 도메인 유사 / 생성일 / 키워드 | 유명 이름(naver)을 따라 한 위험 링크. 모델 확률 값이 들어 있는 경우 | 손으로 작성 (0.91은 가짜 예시 값) |
| `url_whois_fail.json` | 60 | 도메인 유사 / 기관명 불일치 / URL 구조 | 정부기관(gov)을 사칭한 링크. 도메인 조회에 실패해서 생성일을 `unavailable`에 적고, 나머지로만 점수를 낸 경우 | `url_practice.ipynb` 셀 7~10으로 생성 |
| `email_spoof.json` | 70 | SPF 실패 / 보낸 사람 불일치 | 인사팀을 사칭한 위조 의심 메일. 모델이 없어서 `model_probability`가 `null`인 경우 | `email_practice.ipynb`로 생성 |

샘플 3개를 합치면 링크 배점 5개 항목(도메인 유사, 생성일, 기관명 불일치, 키워드, URL 구조)이 모두 한 번 이상 나옵니다.

## 약속 (초안, 팀 합의 후 확정)

1. `score`는 `reasons`의 `points`를 더한 값입니다. 샘플도 이 규칙으로 맞췄습니다.
2. 링크 점수 배점 초안 (항목별 최대 점수): 도메인 유사 35 / 생성일 30 / 기관명 불일치 15 / 키워드 10 / URL 구조 10 (합계 100). 이메일 배점은 B가 정합니다 (현재 샘플의 SPF 실패 40, 보낸 사람 불일치 30은 임시값).
3. 확인하지 못한 항목은 0점으로 처리하지 않고 `unavailable`에 적습니다. 그 항목의 점수는 빠진 채로 계산되므로 **실제 위험보다 낮게 나올 수 있습니다.**
4. JSON 파일 안에는 `//` 같은 설명 줄을 쓸 수 없습니다. 설명은 이 README에만 적습니다.
5. **칸 이름을 바꾸거나 추가하려면** 단톡에 먼저 알리고, 아래 변경 기록에 한 줄 적습니다.
6. 커밋 메시지는 `[담당] 무엇을 했는지` 모양으로 적습니다. 예: `[A] 샘플 3: 이메일 위조 의심 예시 추가`

### 팀이 정해야 할 것

- URL 구조: 하이픈(-) **1개부터** 점수를 줄지, **2개부터** 줄지 (지금 노트북은 1개부터)
- `gov` 하나로 도메인 유사(35)와 기관명 불일치(15)가 **동시에** 걸리는 것이 중복 점수인지
- 이메일 배점 확정 (B)

## 주의

- 샘플은 **가짜 데이터**입니다. 실제 분석 결과나 성과가 아닙니다. 특히 `model_probability`의 0.91은 모델이 계산한 값이 아니라 예시로 적어 둔 값입니다.
- 샘플의 `.example` 주소는 문서·연습용 가짜 주소입니다. 실제 분석 테스트에 쓸 URL은 따로 정합니다.
- 피싱 링크는 **분석만 하고 접속하지 않습니다.** 결과 화면에 파란 링크로 보여도 누르지 않습니다.
- 이 저장소는 **공개(Public)** 입니다. API 키, 비밀번호, 실제 수집한 피싱 데이터, 개인정보는 절대 올리지 않습니다 (비밀 정보는 `.env`에만 적고, `.env`는 `.gitignore`에 들어 있습니다).

## AI 활용 안내

이 프로젝트의 모든 과정에서 사용한 AI 도구는 **Claude (Anthropic, claude.ai 웹 채팅)** 하나입니다.

| 항목 | 내용 |
|---|---|
| 사용 도구 | Claude (Anthropic) |
| 활용 대상 | README와 샘플 초안 작성, Colab 노트북(`url_practice.ipynb`, `email_practice.ipynb`) 코드와 주석 작성, GitHub·Colab 사용법 학습, 저장소 검토 |
| 팀원이 한 일 | 코드를 Colab에서 직접 실행하고 결과 확인, 샘플 내용 선택과 수정, 파일 업로드와 정리, 최종 판단 |
| 검증 방법 | Colab 실행 결과를 예상 결과와 대조, `assert`로 팀 약속 자동 검사, 진짜 사이트·정상 메일을 넣어 오탐(잘못된 위험 판정)이 없는지 시험 |
| 기록 보관 | AI 대화 원본은 삭제하지 않고 심사 종료 후 3개월 이상 보관합니다. 대화별 도구·목적·활용 범위는 AI 활용 기록표(구글 시트)에 적습니다. |

AI가 만든 이미지를 쓰게 되면 실제 활동 사진과 구분해 **"AI 생성 이미지"** 로 표시합니다.
