# Phish&Chips · 캐치피싱(CatchPhish)

AI 기반 피싱 탐지 및 보안 교육 체험 플랫폼 (캡스톤디자인)

- 배포 주소: https://catchphish-three.vercel.app (`/` 첫 화면, `/game` 체험 게임, `/check` 링크 검사, `/admin` 관리자)

## 이 저장소는 무엇인가요?

팀원 3명(A, B, C)의 코드와 문서를 한곳에 모아 두는 보관함입니다.
**`main`에 저장하면 Vercel이 1분에서 3분 안에 웹사이트를 자동으로 다시 배포합니다.** 그래서 서버 코드(`api/`, `backend/`)와 시나리오(`scenarios/`)는 저장하는 순간 실제 사이트가 바뀝니다.

## 결과 형식 (samples/ 폴더)

링크든 이메일이든, 분석이 끝나면 **아래 칸 이름으로 결과를 만든다**는 약속입니다.
이어달리기의 바통 모양을 똑같이 맞추는 것과 같습니다.

```
링크 탐지 엔진 ─┐
                ├─ 결과(JSON 6칸) ──→ 화면에 해설로 보여 줌
이메일 탐지 엔진 ┘                  └→ 장부(DB)에 저장
```

### 칸 설명

| 칸 | 쉬운 뜻 |
|---|---|
| `type` | 링크 검사인지 이메일 검사인지 (`url` 또는 `email`) |
| `input` | 검사한 것 자체 (링크 주소 또는 메일 파일 이름) |
| `score` | 위험 점수 (0에서 100) |
| `model_probability` | AI 모델이 말한 피싱 확률 (0에서 1). 모델이 없으면 `null` |
| `reasons` | 점수가 나온 이유 목록 |
| `unavailable` | 확인하지 못한 항목의 짧은 이름 목록. 없으면 빈 목록 `[]` |

`unavailable`에 쓰는 이름은 코드와 똑같이 맞춥니다: 도메인 생성일 조회 실패 `whois`, 메일 검사 결과 없음 `spf`, 이메일 헤더에 인증 결과 없음 `auth`.

### reasons 안의 칸

| 칸 | 쉬운 뜻 | 예시 |
|---|---|---|
| `factor` | 이유의 이름 | 도메인 유사 |
| `points` | 이 이유로 더해진 점수 | 35 |
| `text` | 사람이 읽는 설명 문장 | 유명 이름과 비슷하지만 똑같지는 않은 도메인입니다. |

## 샘플 3개

| 파일 | 점수 | 이유 | 보여주는 것 | 만든 방법 |
|---|---|---|---|---|
| `url_dangerous.json` | 75 | 도메인 유사 / 생성일 / 키워드 | 유명 이름(naver)을 따라 한 위험 링크. 모델 확률 값이 들어 있는 경우 | 손으로 작성 (0.91은 가짜 예시 값) |
| `url_whois_fail.json` | 60 | 도메인 유사 / 기관명 불일치 / URL 구조 | 정부기관(gov)을 사칭한 링크. 도메인 조회에 실패해서 생성일을 `unavailable`에 적고, 나머지로만 점수를 낸 경우 | `url_practice.ipynb` 셀 7~10으로 생성 |
| `email_spoof.json` | 62 | DMARC 실패 / SPF 실패 / 답장 주소 불일치 | 인사팀을 사칭한 위조 의심 메일. 모델이 없어서 `model_probability`가 `null`인 경우 | `email_practice.ipynb`의 연습 메일을 `email_analyzer.py`(B 확정 배점)로 다시 생성 (10/28) |

샘플 3개를 합치면 링크 배점 5개 항목(도메인 유사, 생성일, 기관명 불일치, 키워드, URL 구조)이 모두 한 번 이상 나옵니다.

## 약속

1. `score`는 `reasons`의 `points`를 더한 값입니다.
2. **링크 배점** (항목별 최대 점수): 도메인 유사 35 / 생성일 30 / 기관명 불일치 15 / 키워드 10 / URL 구조 10 (합계 100)
3. **이메일 배점** (B 확정 10/24): DMARC 실패 28 / SPF 실패 17 / DKIM 실패 0 / 표시 이름 위장 17 / 답장 주소 불일치 17 / 첨부 파일 위험 11 / 긴급성·압박 문구 10 (합계 100). DKIM은 정상 메일에서도 서명이 자주 깨져 오탐을 줄이려고 해설에만 보여 주고 점수에는 넣지 않습니다
4. 확인하지 못한 항목은 0점으로 처리하지 않고 `unavailable`에 적습니다. 그 항목의 점수는 빠진 채로 계산되므로 **실제 위험보다 낮게 나올 수 있습니다.**
5. JSON 파일 안에는 `//` 같은 설명 줄을 쓸 수 없습니다. 설명은 이 README에만 적습니다.
6. **칸 이름을 바꾸거나 추가하려면** 단톡에 먼저 알리고, 아래 변경 기록에 한 줄 적습니다.
7. 커밋 메시지는 `[담당] 무엇을 했는지` 모양으로 적습니다. 예: `[A] 샘플 3: 이메일 위조 의심 예시 추가`

### 팀이 정한 기준 (10/28 확정)

- URL 구조: 하이픈(-)은 **1개부터** 점수를 줍니다
- `gov`가 들어간 주소는 도메인 유사(35)와 기관명 불일치(15)가 **함께** 걸릴 수 있으며, 그대로 둡니다
- 판정 구간: 60점 이상 위험, 30점 이상 주의
- 문자 본문의 압박 문구는 링크 점수에 넣지 않고, 게임 해설에 따로 보여 줍니다 (이메일 엔진과 같은 단어 목록)

## 주의

- 샘플은 **가짜 데이터**입니다. 실제 분석 결과나 성과가 아닙니다. 특히 `model_probability`의 0.91은 모델이 계산한 값이 아니라 예시로 적어 둔 값입니다.
- 샘플과 게임 시나리오의 `.example` 주소는 연습용 가짜 주소입니다. 실제로 등록할 수 없는 주소라 게임에서는 도메인 생성일이 늘 "확인하지 못한 항목"으로 나옵니다. 링크 검사(`/check`)에 실제 주소를 넣으면 생성일까지 분석합니다.
- 피싱 링크는 **분석만 하고 접속하지 않습니다.** 결과 화면에 파란 링크로 보여도 누르지 않습니다.
- 이 저장소는 **공개(Public)** 입니다. API 키, 비밀번호, 회사 코드, DB 주소, 실제 수집한 피싱 데이터, 개인정보는 절대 올리지 않습니다. 비밀 값은 Vercel 환경 변수에만 둡니다.
